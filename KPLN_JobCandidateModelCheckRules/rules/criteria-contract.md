# Контракт критериев и результатов

Критерии определяет задание на проверку. Этот документ задаёт их структуру,
но не добавляет требований к моделированию или шкалу найма.

## Профиль проверки

Профиль хранит `profile_id`, `version`, источник задания и его версию,
дисциплину/уровень задания, область модели и перечень критериев.
Согласованные исключения фиксируются с источником и областью действия.
Если задана балльная оценка, профиль также содержит веса, формулу,
порог и порядок обработки неприменимых/непроверенных пунктов.
Без этих сведений выводить статусы и доказательства без итогового балла.

Для каждого критерия сохранить:

| Поле | Содержание |
|---|---|
| `criterion_id`, `version` | Устойчивый ID и версия требования |
| `source` | Пункт задания, документа или указание проверяющего |
| `scope` | Категории, семейства, типы/экземпляры, хост/связи, условия применимости |
| `required_data` | Нужные поля и достаточная полнота выборки |
| `method` | Формальная проверка или экспертная оценка; точное правило сравнения |
| `expected` | Ожидаемое состояние, единицы и допуск, если они нужны |
| `severity` | Значимость из задания; при отсутствии — не задана |
| `evidence` | Данные, достаточные для подтверждения вывода |

Не задавать условный нулевой допуск вместо неизвестного инженерного допуска.
Точное совпадение строк/кодов допустимо, если именно оно требуется критерием.
Устные уточнения проверяющего фиксировать как источник изменения профиля.

## Статусы

| Статус | Когда применять |
|---|---|
| `pass` | Достаточные данные подтверждают критерий во всей заявленной области |
| `fail` | Подтверждено нарушение применимого критерия; есть факт и источник требования |
| `not_applicable` | Доказано, что условие применимости не выполнено |
| `not_checked` | Не хватает требования, данных, возможностей чтения или полноты выборки |
| `needs_review` | Данные есть, но неоднозначность требует экспертного решения |

Частично проверенный критерий с найденным нарушением может иметь `fail`,
но обязан отдельно указывать неполное покрытие. Частичная выборка без
нарушений не даёт `pass` для всей модели. Исключение фиксируется отдельно;
оно не стирает наблюдение и не превращает его автоматически в `pass`.

Результат хранит `criterion_id/version`, `status`, `expected`, `actual`,
`element_unique_ids`, `evidence_refs`, `coverage` и объяснение. Для
`not_checked` дополнительно указать недостающие данные/возможность,
для `needs_review` — вопрос, который должен разрешить проверяющий.
