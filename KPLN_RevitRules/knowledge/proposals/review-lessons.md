# Наблюдения из проверенных задач

## 2026-09-29 — подбор Nevatom KT

Источник: технические данные Nevatom `NT25-008739-01` от 11.09.2025 и
пользовательская проверка универсального одноуровневого семейства. Все 20
подборов KT получили однозначный тип по ID установки либо по системе и
нормализованной марке. Смешение латинских и кириллических символов в марках —
реальный случай, поэтому буквальное сравнение строк недостаточно.

Поля теплообменников вида `A (B)` нельзя сворачивать в одно значение. В этом
шаблоне первое число согласовано с выбранными температурами, второе — со
справочной точкой производителя. Для модели используется первое, оба остаются
в записи доказательств.

Отдельный лист П8 оказался предложением серии SL и не относится к семейству
KT. Совпадение проекта и номера системы само по себе не разрешает перенос между
сериями.

Подробная область применения и таблица параметров закреплены в
`rules/nevantom-kt-family-mapping.md`. Идентификаторы реальной модели и полный
отчёт сравнения остаются в игнорируемой локальной записи.

## 2026-09-30 — связи патрубков водяного нагревателя

Вложенная секция имеет четыре read-only смещения `Вода_Соединител1/2_смещение
X/Y`, управляемые родителем. Численно подтверждено соответствие Y1 притоку,
Y2 обратке; продольные системные формулы добавляют локальный X к началу
первой найденной секции нагревателя. Значения шаблона нельзя считать
подобранными по документу производителя. Последующее чтение разных X1/X2
подтвердило приток/обратку. Пользователь задал правило при отсутствии
координат производителя. Актуальное уточнение от 01.10.2026: X=L/2 для обоих,
Y притока=H-1.25D притока, Y обратки=1.25D обратки; H — Установка_Высота.
Приток сверху, обратка снизу, от низа корпуса. Старое правило H/2±50 отменено. Подробности, область действия и
ограничения: `rules/water-heater-connectors.md`.

## 2026-10-01 — патрубки охладителя и дренажа

Пользователь задал X обоих Фреон_Патрубок=L/4, Y притока=H-1.25D притока,
Y обратки=1.25D обратки. Для Дренаж_Патрубок X=L/2, Y=1.25D дренажа.
L — длина своей секции, H — Установка_Высота, D — диаметр дренажа.
Подробности и ограничение проверки по сохранённому снимку:
[правило](../../rules/cooling-drain-connectors.md). Эти назначения заменяют
прежнее сохранение унаследованных смещений при отсутствии размеров в подборке.

Уточнение 01.10.2026: все условные координаты воды, фреона и дренажа
применяются только при отсутствии данных каталога для соответствующей оси.
Если размеры/привязки есть, смещения рассчитываются по ним относительно
базы семейства; неоднозначность каталога не равна отсутствию данных.

## Уточнение диаметра и оси
В последнем указании пользователь назвал X, но заменяемые 3/4 высоты и
направления вверх/вниз относятся к Y. Продольные правила X сохраняются.
«Диаметр подключения» означает диаметр конкретного патрубка: для воды общий
Вода_Патрубок_Приток/Обратка_Диаметр, для охлаждения отдельные диаметры
Фреон_Патрубок_Приток_Диаметр и Фреон_Патрубок_Обратка_Диаметр,
для дренажа Дренаж_Патрубок_Диаметр. Использовать диаметр, не радиус.
Приток сверху: Y=H-1.25D притока. Обратка снизу: Y=1.25D обратки.
Для дренажа сохраняется Y=1.25D дренажа.
Если диаметр неизвестен, не угадывать его и не возвращаться к правилу четвертей.
Это условное размещение только при отсутствии данных каталога для данной оси.
## Связанные параметры: пересчёт целого типоразмера
Указание пользователя 01.10.2026, подтверждённое его ручной проверкой:
промежуточное сочетание старых и новых размеров может вызвать ошибку Revit,
хотя итоговый набор корректен. Для одного типоразмера сначала подготовить
полный набор связанных изменений, затем записать все значения и лишь после
этого явно пересчитать и проверить типоразмер. Не разбивать такой набор
на отдельные команды/транзакции с пересчётом после каждого параметра.
Чтение результата, проверка формул и геометрии выполняются после полного набора.
Это не разрешение игнорировать предупреждения окончательного состояния,
удалять проблемные элементы или отключать откат.
Сам факт отката не доказывает дефект семейства: проверить промежуточные
состояния и порядок записи. В проверенном FamilyTypeService явный Regenerate
уже вызывается после цикла Set всех параметров типа; внутренний пересчёт
зависимостей Revit внутри Set этим наблюдением не исключён и требует диагностики.
Ручная успешная проверка пользователя — отдельное свидетельство, не подтверждение
успешной записи через API. Не сообщать об исправлении моста без изменения и проверки.
