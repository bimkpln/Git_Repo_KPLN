# Генерация и заполнение типоразмеров семейств

Этот слой обслуживает создание и изменение типоразмеров по исходным данным.
Проверка моделей кандидатов на работу ведётся отдельно в
`KPLN_JobCandidateModelCheckRules`; правила заполнения не становятся критериями
оценки кандидата автоматически. Оба процесса используют `KPLN_RevitMcpBridge`.

## Источники и выбор правил

Перед работой прочитать [revit-policy.md](revit-policy.md) и
[review-lessons.md](../knowledge/proposals/review-lessons.md).
Определить семейство, документ, базовый тип, требуемые типоразмеры и источники
значений. Сохранить связь «документ/страница → значение → параметр/тип».
Для каждой величины отличать данные производителя, вычисленные значения,
разрешённые условные назначения и унаследованные неподтверждённые значения.

Читать предметные правила по задаче:

| Задача | Правило |
|---|---|
| Подбор Nevatom KT и проверенное универсальное семейство | [nevantom-kt-family-mapping.md](nevantom-kt-family-mapping.md); разбор и сравнение — `src/nevantom_selection.py` |
| Мощность и расход секций по подбору | [thermal-section-units.md](thermal-section-units.md) |
| Диаметры подключений исследованного универсального семейства | [connection-diameters.md](connection-diameters.md) |
| Смещения патрубков водяного нагревателя | [water-heater-connectors.md](water-heater-connectors.md) |
| Смещения охладителя и дренажа | [cooling-drain-connectors.md](cooling-drain-connectors.md) |

Учитывать область применения каждого правила. Для другого семейства/серии
сначала установить соответствие параметров, единиц, секций и координат.
Не переносить частные коэффициенты или имена параметров по внешнему сходству.

## Работа с общим мостом

Привязать сессию и документ через `list_revit_sessions` и `get_revit_context`.
В редакторе семейства читать `get_revit_family_document`: значения, формулы,
идентификаторы и доступность параметров каждого типа. В проекте читать типы
через `get_revit_family_types` и `get_revit_elements`; параметры экземпляров
не подменяют параметры типа.

Для нового типа в открытом редакторе семейства использовать
`create_revit_family_types` с явно выбранным `base_type_name`. Для существующего
типа — `set_revit_family_type_parameters`. В проекте доступные параметры
существующего элемента типа менять через `set_revit_parameters`.
Создание типов в проекте не считать поддержанным только потому, что есть
команда создания типов в редакторе семейства.

Пакет формировать из свежего чтения с `expected_revision`, а для изменения
существующего значения — с точным `expected_value`. Сначала `dry_run=True`,
затем применение в рамках уже разрешённой задачи без повторного согласования.
Связанные диаметры, размеры и смещения одного типа подготовить вместе;
соблюдать правило пересчёта целого типоразмера из общей политики.
Лимиты пакетов брать из актуальной схемы инструмента.

После применения перечитать значения, формулы и доступные данные геометрии.
Разделять успешную запись чисел и проверку фактических соединителей/геометрии:
неизвлечённые данные остаются непроверенными. После таймаута пользоваться
`get_revit_operation` согласно общей политике. Мост не сохраняет файл.

## Результат и развитие

Отчёт: созданные/изменённые/совпадающие типы, происхождение значений,
неизвестные данные, результат повторного чтения и границы проверки.
Снимки, планы и отчёты хранить в игнорируемом `local/`; происхождение знаний
фиксировать `src/create_record.py`. Новые общие решения добавлять в правила
с областью действия и источником, наблюдения — в `knowledge/proposals`.
