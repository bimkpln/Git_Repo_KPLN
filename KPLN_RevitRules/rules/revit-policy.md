# Работа с Revit через KPLN_RevitMcpBridge

## Границы знаний

Версия 1.0.0 задаёт порядок работы с данными и изменениями. Она не содержит
обученных инженерных правил, допусков, требований к LOD, именованию или
универсальных решений о корректности семейств. Требования проекта берутся
из предоставленных документов и указаний пользователя, с указанием источника.
Отсутствующее требование нельзя подменять общим предположением.

## Привязка к модели

Начать с list_revit_sessions и get_revit_context. Если сессий несколько,
выбрать требуемую по версии и открытому документу. Сохранить session_id,
document_id и revision. document_id — идентификатор открытого документа
в текущей сессии, а не постоянный GUID файла. Перезапуск требует нового чтения.

Для элементов использовать UniqueId; числовые ElementId передаются строками,
чтобы не терять точность 64-битных ID Revit 2024. Параметры выбирать по id из
get_revit_elements, поскольку имена могут повторяться. Параметры экземпляра
и типа различать; запись параметра типа затронет все его экземпляры.
Для получения элемента типа использовать find_revit_elements с
element_types_only=True и сопоставить id с type_id исходного элемента.

Страницы одного набора сравнивать при одинаковой revision. Если revision
сменилась, заново прочитать данные, которые обосновывают решение.

## Единицы и геометрия

Габариты и расположение — миллиметры в внутренних координатах документа.
Bounding box не доказывает точное пересечение, форму или направление короткого
элемента. Для связей учитывать transform; связь и хост имеют разные системы
координат. Не выдавать расчёт по габаритам за проверку точных тел.

Double-параметры выдаются в внутренних единицах Revit; data_type помогает
определить физическую величину. Длина — футы, угол — радианы. Для других величин
не угадывать преобразование. display_value предназначено для просмотра и может
зависеть от локали. Для записи явно указать value_units=revit_internal.
Null означает отсутствие значения, а не ноль. Команда записи не очищает значение
через null; строковый параметр допускает пустую строку.

## План и применение

В рамках разрешённой пользователем задачи прочитать текущие параметры,
зафиксировать источник требования, подготовить пакет с expected_value и
expected_revision и вызвать set_revit_parameters с dry_run=True.
Если действие уже разрешено, применить dry_run=False без повторного запроса
того же разрешения. Если объём изменений выходит за согласованную задачу,
сначала показать конкретный план и уточнить этот объём.

Предпросмотр проверяет входные значения и доступность параметров, но не
выполняет транзакцию: ограничения Revit проверяются при применении. Мост
откатывает весь пакет при ошибке, предупреждении или расхождении результата.
После успеха перечитать изменённые параметры. Сохранение файла и синхронизация
с центральной моделью выполняются отдельно — мост их не вызывает.

После queue_timeout команда отменена до начала выполнения. После
outcome_pending или сетевого таймаута прочитать get_revit_operation.
Результаты доступны минимум 15 минут, пока мост не перезапущен. Если результат
утрачен, перечитать модель перед новым планом; повтор записи вслепую запрещён.

## Развитие знаний

Хранить: наблюдение, источник, область применимости, предлагаемый вывод,
недостающие данные и явно разрешённое действие. Решения человека/агента
отделять от проверок кода. Заметки в knowledge/proposals не становятся
универсальным правилом автоматически. Для анализа создать запись через
src/create_record.py: она фиксирует версию, Git HEAD, dirty state, fingerprint
знаний, хеш входных данных и контекст проекта. Содержимое local/ не публиковать
в общем репозитории без отдельной подготовки.
