# Мощность и объёмный расход секций установки

## Область действия
Указание пользователя от 01.10.2026. Применяется при заполнении установок по
подбору производителя, независимо от серии и настроек отображения единиц.
Не расширяет геометрическую область правила Nevatom KT.

## Условия заполнения
- Есть секция нагрева: заполнить КП_И_Тепловая мощность и, если предусмотрен
  жидкостный контур, КП_И_Расход теплоносителя.
- Есть секция охлаждения: заполнить КП_И_Холодильная мощность и объёмный расход
  соответствующего контура в КП_И_Расход холодоносителя.
- Мощность теплообменника не подменять электрической мощностью двигателя.
  Расход жидкости/хладагента не подменять расходом воздуха.
- Если параметр неприменим (например, расход жидкости у электрического нагрева),
  данных нет, единица неизвестна или контур неоднозначен — не придумывать число
  и не заменять его нулём. Зафиксировать причину незаполнения.
- Отсутствующая секция не разрешает автоматическое обнуление ранее введённых
  данных. Несколько секций/контуров требуют явного соответствия; не суммировать
  их автоматически в один параметр.

## Нормализация единиц
Сохранять исходное число, единицу, страницу, секцию и расчётную точку.
Контрольные единицы по требованию пользователя: мощность кВт, расход м³/ч.
Строгие единицы СИ для сравнения при необходимости — Вт и м³/с.

Сначала привести единицы каталога к контрольным:
- Вт / 1000 = кВт; МВт * 1000 = кВт.
- м³/с * 3600 = м³/ч; л/с * 3.6 = м³/ч;
  л/мин * 0.06 = м³/ч; л/ч / 1000 = м³/ч.
- Для иных единиц использовать проверенное преобразование, учитывая конкретное
  определение единицы; неоднозначные обозначения не угадывать.
- Массовый расход кг/ч или кг/с нельзя считать объёмным. Нужна плотность именно
  данного вещества при расчётных условиях: Q = m / rho с согласованными единицами.
  Без этих данных запись расхода блокируется.
- Значения A (B) не выбирать механически: определить расчётную точку по шаблону.
  Для проверенного шаблона Nevatom использовать A, B хранить как reference.

## Запись и проверка Revit
1. Из свежего чтения определить ID, StorageType, назначение/физическую величину,
   доступность и формулу параметра. Не выбирать параметр лишь по похожему имени.
   При отсутствии metadata типа величины использовать проверенное сопоставление
   данного семейства; неоднозначность блокирует автоматическую запись.
2. Для Double переводить нормализованное значение через Revit UnitUtils:
   ConvertToInternalUnits(valueKw, UnitTypeId.Kilowatts) либо
   ConvertToInternalUnits(valueM3h, UnitTypeId.CubicMetersPerHour).
   Для Revit 2020 использовать соответствующий DisplayUnitType.
3. Display_value, округление, запятая/точка, формат семейства и формат проекта
   не являются основанием для числового преобразования. Не менять настройки
   отображения без отдельного запроса. Не передавать число каталога напрямую
   как внутреннее значение и не использовать SetValueString для этой операции.
4. Подготовить dry_run с expected_value и expected_revision. Записывать только
   отличающиеся значения, value_units=revit_internal. Совпадающие значения
   считать уже заполненными; повторная запись не нужна.
5. После применения перечитать. ConvertFromInternalUnits в кВт и м³/ч должен
   возвращать нормализованное исходное число. Сравнивать не округлённые строки,
   а числа, учитывая лишь вычислительную погрешность преобразования.
6. В отчёте сохранять исходное значение с единицей, нормализованное, внутреннее,
   прочитанное обратно и итог сравнения. Инженерный допуск не выводить из
   форматирования интерфейса. Отдельно учитывать, что параметр экземпляра
   в редакторе семейства задаёт значение по умолчанию, а существующие экземпляры
   проекта могут иметь собственные значения.

## Обязательный перенос диаметров
Применять [connection-diameters.md](connection-diameters.md): общий диаметр
водяного нагревателя, отдельные диаметры охлаждения и диаметр дренажа переносить
из подбора. После изменения диаметра пересчитывать зависимые условные смещения
в том же пакете. Неизвестный диаметр не считать заполненным по каталогу.
