# KPLN_ViewsAndLists_CopyByLevels

Бета 0.1.0. Создание листов по этажам на основе выбранного эталонного листа.
Самостоятельный модуль KPLN_Loader; работает непосредственно через Revit API, без MCP и внешнего сервиса.

## Подключение

Кнопка **«Листы по этажам»** добавляется на существующую панель **«Виды и листы»**.
Панель принадлежит `KPLN_ViewsAndLists_Ribbon`. Новый модуль не создаёт вторую панель и не требует ссылки на DLL Ribbon.
Если новый модуль загрузился раньше Ribbon, добавление кнопки откладывается до Idling. При отсутствии панели появляется сообщение.

Зависимости: `KPLN_Loader` и `KPLN_Library_Forms` соответствующего года Revit. В сборках установлено `Private=False`;
посторонние версии этих DLL и Autodesk DLL в каталог нового модуля копировать не нужно.

Для регистрации через действующий загрузчик КПЛН:

- `Name`: `KPLN_ViewsAndLists_CopyByLevels`;
- `Path` для бета-сборок: `X:\BIM\5_Scripts\Git_Repo_KPLN\KPLN_ViewsAndLists_CopyByLevels\bin\Debug`;
- `IsLibraryModule`: `False`, `IsDebugMode`: `True`, `IsEnabled`: `True`;
- назначить модуль пользователю-тестировщику штатными средствами администрирования загрузчика;
- перезапустить Revit с включённым модулем `KPLN_ViewsAndLists_Ribbon`.

В `Path` передаётся родитель каталогов `2020`, `2023`, `2024`, `2026`, а не файл DLL.
Для Release путь заканчивается на `bin`. Файлы проекта и сборки не регистрируют новую запись в БД загрузчика автоматически.
В общей папке выпуска DLL не заменяются.

## Первый запуск

1. Открыть подготовленный лист и нажать «Листы по этажам».
2. Проверить эталон и основной план. Главный план предварительно выбирается по площади окна.
3. На вкладке этажей проверить галочки, отметки и обозначения этажей. Автовыбор идёт вверх от уровня основного плана;
   шаг 1,5 м считается от последнего автоматически выбранного уровня. Ручной выбор не ограничен этим шагом.
4. На вкладке состава определить действия для дополнительных видов. Общая легенда используется повторно;
   обычный вид создаётся независимой копией или заменяется выбранным неразмещённым видом.
5. На вкладке экспликаций выбрать спецификацию и открыть настройку фильтров. Отдельно выбрать каждое изменяемое условие.
6. Пересчитать значения по маскам, проверить строки выбранных этажей, при необходимости исправить отдельные значения.
7. Задать начальный номер, префикс и маски имён. Для примера МТРС можно начать с 5, оставив номер 4 под теплоснабжение.
8. Сформировать предпросмотр. Номера и названия можно изменить непосредственно в его таблице.
9. Нажать «Создать листы». После выполнения открывается первый созданный лист и полный отчёт.

Маски: `{Этаж}`, `{Уровень}`, `{Отметка}`, `{Типовые}`, `{Исходное}`, `{Индекс}`.
Например, фильтр номера помещения `1.1.{Этаж}.` даст `1.1.2.` для этажа 2.
Текст «Типовой 2–5, 8–12 этажи» вводится в колонку подписи типовых этажей полностью;
он включается в название через `{Типовые}`, но не меняет состав экспликации на объединение этажей.
Нумерация листов не совпадает автоматически с номерами этажей и не перенумеровывает существующий выпуск.

## Что переносится

- Для Revit 2023/2024/2026 используется `ViewSheet.Duplicate(DuplicateSheetWithDetailing)` с последующим восстановлением состава видов.
  Штамп, параметры и оформление листа копируются штатным механизмом Revit.
- Для Revit 2020 лист создаётся заново, доступные элементы листа копируются `CopyElements`; параметры листа переносятся отдельно.
- План создаётся через `ViewPlan.Create` на целевом уровне. Сохраняется назначенный шаблон,
  применяются доступные настройки эталона, переносится цельная обрезка/область видимости и диапазон.
- Явные уровни диапазона преобразуются в смещения от нового уровня; специальные относительные ссылки сохраняются.
  Если шаблон не позволяет установить требуемый диапазон, этаж откатывается с объяснением.
- Виды размещаются с типом и поворотом исходного окна. В 2023+ переносятся смещение и длина заголовка;
  этажные планы совмещаются по общей модельной точке внутри контура. В 2020 сохраняется центр окна.
- Независимая графика плана: тексты, линии детализации, заполненные области, изображения, общие аннотации.
  Ошибка отдельного такого элемента отражается в отчёте, его пробное копирование откатывается.
- Спецификация дублируется целиком. Изменяются только отмеченные строки фильтров, сохраняются операторы,
  остальные фильтры, структура, оформление и сортировка. После записи перечитываются фактические фильтры.
- При управлении фильтрами шаблоном создаётся отдельная копия шаблона с отключённым управлением фильтрами.
  Общий исходный шаблон не изменяется.

Каждый лист вместе с его новыми видами и спецификациями создаётся в одной транзакции.
Ошибочный этаж откатывается полностью; успешные этажи сохраняются в общей группе с одной командой Undo.
Непустые предупреждения Revit записываются в отчёт, ошибки вызывают откат этажа.
Признак исходного листа и целевого уровня хранится в Extensible Storage. Повторный запуск умеет пропускать ранее созданные листы.
Автоматического обновления уже оформленных вручную листов в бете нет.

## Границы беты

- Марки и размеры, ссылающиеся на модель, не перепривязываются к элементам нового этажа. Они считаются в отчёте и оформляются отдельно.
- Дополнительный разрез/узел в режиме независимой копии остаётся в исходной области модели.
  Для другого этажа нужно выбрать готовый вид либо оформить узел отдельно. Общая замена обычным видом рассчитана на один создаваемый лист;
  многократное размещение доступно для легенд.
- Разделённые обрезки и спецификации с сегментами отклоняются до запуска. Вложенная спецификация сохраняется как часть копии,
  но её собственные фильтры пока не редактируются этим окном.
- Повернутая относительно создаваемого вида ориентация плана отклоняется, если настройки эталона не воспроизводят её автоматически.
- Фильтры по уровням связанных файлов не сопоставляются автоматически с уровнями основной модели.
  Режим «Целевой уровень» разрешён только для ссылочного фильтра по уровню текущего документа.
- Настройки связей, отображаемых «По связанному виду», нужно проверить в Revit: шаблон может указывать на фиксированный связанный план.
- Свободный текст переносится без смысловой замены номера этажа, отметки или номера узла внутри текста.
- Проверка компоновки сравнивает прямоугольные габариты окон/заголовков и спецификаций с листом и друг с другом.
  Она выдаёт предупреждения и не заменяет визуальную проверку области штампа, линий рамки и реального содержимого.
- Общая спецификация или копия с полностью сохранёнными фильтрами может показывать исходный этаж.
  Предпросмотр явно сообщает о копиях без изменяемых условий; этажный фильтр выбирает пользователь.

## Настройки и отчёты

`%LOCALAPPDATA%\KPLN\KPLN_ViewsAndLists_CopyByLevels\Settings` — настройки по документу и исходному листу.
Сохраняются основной план, выбор этажей, маски, действия с видами и правила фильтров/ручные значения.
Настройки записываются при нажатии «Создать листы». Привязки сохраняются по UniqueId; фильтр дополнительно проверяется по полю и условию.

`%LOCALAPPDATA%\KPLN\KPLN_ViewsAndLists_CopyByLevels\Reports` — текстовые отчёты о создании, пропусках, предупреждениях и откатах.

## Сборка и устройство

В решении только этот модуль. Готовые библиотеки КПЛН подключены через `Reference/HintPath` и не пересобираются вместе с модулем.
Конфигурации: `Debug2020`, `Revit2020`, `Debug2023`, `Revit2023`, `Debug2024`, `Revit2024`, `Debug2026`, `Revit2026`; платформа `x64`.
2020/2023/2024 — .NET Framework 4.8; 2026 — .NET 8 с общим `build/KPLN.Revit2026.props` репозитория.

```powershell
MSBuild.exe KPLN_ViewsAndLists_CopyByLevels.sln /t:Build /p:Configuration=Debug2023 /p:Platform=x64
MSBuild.exe tests\NamingRulesTests.csproj /t:Build
tests\bin\NamingRulesTests.exe
```

`Module` отвечает за кнопку. `CopyByLevelsExtCmd` открывает модальное WPF-окно и запускает генерацию в API-контексте команды.
`SourceReader` читает эталон, `CopyByLevelsVM` формирует предпросмотр, `PlanService` создаёт планы,
`ScheduleService` копирует спецификации и заменяет фильтры, `GenerationService` собирает лист и контролирует транзакции.
`SettingsService` хранит настройки; `NamingRules` не зависит от Revit и имеет отдельные исполняемые тесты.

Проверки: сборка с настоящими API всех четырёх годов; тесты выбора уровней и подстановок; визуальная проверка пяти WPF-представлений
на тестовых данных вне Revit. Фактическое создание листов в модели и работа кнопки в загруженной ленте — предмет пользовательского бета-теста.
