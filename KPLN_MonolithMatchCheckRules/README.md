# KPLN_MonolithMatchCheckRules

Для запуска через Codex и продолжения разработки использовать
[общие наработки](development/README.md) и
[локальный расчёт с контрольными точками на X](rules/common/local-first.md).
Расчёты выполняются на C сотрудника; перенос не объявляет движок завершённым.

Доработки сотрудников сохраняются отдельно от общей версии:
[порядок подготовки и разбора предложений](rules/common/contributions.md).
Общее хранилище пакетов — `local/contributions/`; эти предложения не применяются
в других проверках автоматически. Для включения нужен отдельный разбор и выпуск.

Общие правила проверки совпадения монолитных конструкций АР/КР в NWD.
Один скилл, отдельные профили ПД/РД; версия в VERSION.

Для всех новых и контрольных проверок действуют
[принципы организации расчёта и сокращения повторной работы](rules/common/execution-efficiency.md).

Для сотрудников, запускающих проверку через Codex:
[подключение к текущим наработкам](development/README.md).
Для проекта `Сочи гостиница Москва` действует отдельное
[направленное правило отверстий КР 200 мм / перемычек АР 300 мм](rules/projects/sochi_moskva.md).
Оно не переносится на другие проекты и не означает готовности полного движка.

**Готовность:** методика, профили, входной контроль, история и подготовка
запуска реализованы и протестированы. Универсальный расчёт нового NWD и выпуск
двух отчётов одной командой пока не реализованы. Первый новый объект потребует
подключения и приёмки геометрического движка; наличие скилла не заменяет это.
Подробнее: [границы реализации](rules/common/readiness.md).

## Подключение сотруднику

На компьютере с доступом к этой папке выполнить в PowerShell:

```powershell
& 'X:\BIM\5_Scripts\Git_Repo_KPLN\KPLN_MonolithMatchCheckRules\scripts\install-skill.ps1'
```

Установщик размещает короткий скилл в `$env:USERPROFILE/.agents/skills`,
сохраняет резервную копию прежней установки и ссылку на общие правила.
Другой путь можно указать через `-SkillDirectory`. Старую установку того же
скилла по другому пути не дублировать; указать её как SkillDirectory.
Диск X у коллеги должен вести к тому же общему хранилищу; допустим UNC-путь.
Новый чат рекомендуется открывать после установки. Если скилл не появился,
перезапустить Codex или передать полный путь к SKILL.md в сообщении.
Официальное описание обнаружения скиллов: https://learn.chatgpt.com/docs/build-skills

## Новый чат и другой объект

Подробная пошаговая инструкция: [docs/START_HERE.md](docs/START_HERE.md).
Запуск с заранее заполненной формой в поле ввода (путь — локальная папка проекта):

```powershell
& 'X:\BIM\5_Scripts\Git_Repo_KPLN\KPLN_MonolithMatchCheckRules\scripts\new-check.ps1' -Workspace 'C:\BIM\MonolithChecks'
```

Папка должна уже существовать. Новый чат получает форму, но сообщение не
отправляется автоматически. Заполнить поля, затем нажать «Отправить».
Обычная кнопка создания пустого чата не заменяется этим запускателем.
Штатного механизма ответа ассистента до первого сообщения скилл не использует.
Документация: https://learn.chatgpt.com/docs/reference/commands

Можно создать новый чат в существующем проекте. Для независимых объектов
удобнее отдельные локальные рабочие папки; общими остаются правила и реестры.
Скопировать [шаблон запроса](examples/start-request.txt), заполнить проект,
стадию, корпус/секцию, путь NWD и корневую папку отчётов объекта. Для каждой
проверки создаётся `дата_Монолит_Фулл/Лайт_область`; подробнее
[правила папок](rules/common/result-folders.md). Для рабочей ПД приложить
планы/разрезы; для РД они не ограничивают проверку. Указать, первичная это
проверка или контрольная. При контрольной использовать тот же ключ реестра.

Общий реестр по умолчанию находится в `local/shared-state/registries` этой
папки и исключён из Git. При отдельных Git-копиях на компьютерах обязательно
настроить ОДИН общий state_root; иначе история у сотрудников разойдётся.
Не менять ключи проекта/корпуса между итерациями; отображаемые названия могут
быть русскими, технические ключи фиксируются при первой проверке.
Реестр СГРВН/ПД/К2/С14 уже перенесён сюда с разрешения владельца.

## Исполняемые команды

Python 3.10+ без сторонних библиотек достаточен для модулей этого пакета.
Команды выполняются из корня пакета; `python` можно заменить путём к Python.

```powershell
python -B -m unittest discover -s tests -v
python -B scripts/prepare-run.py --config <config.json> --nwd <model.nwd> --output <новая_папка_запуска> --operator <имя>
python -B <папка_запуска>/rules_snapshot/scripts/lib/preflight.py <папка_запуска>/run.json <raw_nwd_json> <preflight.json>
```

Для автоматического создания папки вместо --output указать --results-root
с корнем отчётов объекта. В конфигурации result_scope_label (например К2С14),
check_variant (full/lite), additional_exclusions (список, обязательный для lite).

prepare-run фиксирует хеш NWD, область реестра, профиль, автора, время,
версию и копию правил. Он НЕ вычисляет несовпадения и честно записывает
`prepared_not_checked`. Примеры конфигураций — examples/rd.json и pd.json;
координаты видов в примере ПД условные, их нельзя использовать для модели.

## Изменения и совместная работа

Редактировать общие rules/scripts/tests, проверять примерами, повышать VERSION
и описывать изменение в CHANGELOG. Запущенная проверка продолжает работать
со своей копией правил; новая использует обновлённую версию. Не редактировать
реестры вручную: подготовка транзакции, проверка обоих отчётов и commit описаны
в rules/common/history.md. Скилл не меняет KPLN_Clashes_Ribbon.
