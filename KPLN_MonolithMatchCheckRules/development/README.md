# Общие наработки, локальная работа

Это перенесённая исследовательская реализация СГРВН и СГМ. Она позволяет начать
с существующего кода, не требует доступа к диску C автора и не обещает готовый
универсальный расчёт любого нового объекта. Сотрудник задаёт данные; Codex
адаптирует рабочую копию и проверяет результат по общим правилам.

Точные ID опубликованных снимков и пути — CURRENT.json. Использовать только
проверенный checkpoint с READY.json. Архивы находятся в `local/workspace-store`
относительно общего пакета. В коде сохранена структура iteration2…iteration8,
distribution, workflow, handoff и необходимые источники парсера плагина.
Снимок кода не включает пользовательские настройки Codex, историю чатов,
лицензионные сборки установленного Autodesk и личные браузерные профили.

## Новый компьютер / объект

1. Создать локальную рабочую папку сотрудника. Получить основной NWD и входные
   данные. Прочитать общий SKILL.md и зафиксировать актуальные правила.
2. Восстановить код из CURRENT.json через scripts/lib/workspace_checkpoint.py
   restore в пустую папку. Для нового объекта не восстанавливать чужие runs,
   проектные реестры и адресные решения. Восстановить `.geometry_deps` из снимка
   данных отдельно во временную пустую папку и перенести эту папку зависимостей
   в свою рабочую копию после сверки хешей. Это Windows x64 CPython 3.12.
3. Проверить Python/runtime через доступные средства Codex или установленный
   Python. Для bundled runtime используется scripts/run-research.ps1 с явным
   -Workspace; PythonHome выбирается для текущего сотрудника. PythonRunner
   требует python312.dll. Проверить numpy, Pillow и нативные геометрические
   библиотеки; зафиксировать версии. Список — runtime_requirements.txt и
   актуальный handoff/transfer_checkpoint_20261026/dependencies.json.
4. Проверить установленный Navisworks Manage и его .NET/COM API; исходный
   стенд — Manage 2023. На иной версии нужна проверка совместимости и локальная
   сборка читателя. Autodesk не устанавливается копированием чужих DLL.
   Revit/RVT и старые revit_source_reader/revit_readonly_smoke не запускать.
5. Общие математические блоки брать из принятой версии правил. Для архитектуры
   прежнего расчёта читать iteration7/README.txt; для СГМ — handoff и iteration8.
   b1_*/sgm_* и прежний К2С14 содержат проектные контексты: не запускать их на
   другом здании заменой одного пути. Создать отдельный контекст нового объекта,
   переиспользовать готовые этапы, доработать недостающее и проверить результат.
6. Для браузерной проверки определить Node/playwright/браузер на своём ПК.
   Исторические QA-скрипты могут содержать абсолютные пути автора; адаптировать
   локально, не объявлять их работоспособными без проверки. Параметры/Navisworks
   пути и старые журналы не переписывать в доказательствах прежних запусков.

Пример вызова Python после восстановления (для Codex, не обязательный ручной шаг):
`scripts/run-research.ps1 -Workspace C:\BIM\MonolithChecks -c "import numpy, shapely, trimesh, manifold3d, scipy, rtree; print('runtime OK')"`

## Продолжение и публикация

На ПК автора локальный каталог сохраняется; архивы на X — восстановление и
общий доступ, не основание переносить вычисления в сеть. После законченного
этапа сохранять checkpoint и описание продолжения. СГМ — SGM_RESUME.md.
Собственные доработки коллег хранятся отдельно в local/contributions; повторное
использование — rules/common/local-first.md. Перенос наработок не равен их приёмке
для всех моделей. CURRENT указывает стартовую базу, новые экспериментальные
checkpoint не заменяют её автоматически. При явном поручении на обновление
базы сначала проверить пакет, сохранить старый CURRENT и обновить указатель.

Исторические snapshots правил и результаты расчётов неизменяемы. Копии реестров
в архиве — только история; основной реестр остаётся в local/shared-state.
