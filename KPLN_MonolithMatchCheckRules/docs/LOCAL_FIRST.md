# Контрольные точки и восстановление

Расчёт выполняется на локальном диске. Общие материалы на X доступны также по
UNC `\\fs01\bim_data\BIM\5_Scripts\Git_Repo_KPLN\KPLN_MonolithMatchCheckRules`.
Ниже служебные команды для Codex, сотрудник не обязан запускать их вручную.

`scripts/lib/workspace_checkpoint.py` работает на Python 3.10+ без сторонних
пакетов. Выбор файлов — JSON с workspace_id, include (относительные файлы/папки)
и exclude_prefixes. Не выбирать личные настройки, секреты, браузерные профили,
папку создаваемой очереди, .git или неподконтрольные внешние ссылки.
Исходная выборка должна быть неподвижной на время build. Скрипт проверяет
перечень, размеры/время и хеши при чтении; он не блокирует сторонних писателей.

```
python scripts/lib/workspace_checkpoint.py build --root LOCAL --config SELECTION.json --out NEW_CHECKPOINT
python scripts/lib/workspace_checkpoint.py publish --checkpoint NEW_CHECKPOINT --remote SHARED_STORE
python scripts/lib/workspace_checkpoint.py build --root LOCAL --config SELECTION.json --out NEXT_CHECKPOINT --baseline PUBLISHED_LOCAL_CHECKPOINT
python scripts/lib/workspace_checkpoint.py restore --remote SHARED_STORE --id CHECKPOINT_ID --out NEW_EMPTY_WORKSPACE
```

Для частичного восстановления добавить `--prefix iteration8` или несколько
`--prefix`. Проверяются архивы и каждый восстановленный файл. Восстановление
только в пустую папку, без изменения существующего рабочего каталога. Текущее
состояние архива определяется манифестом, удалённые файлы базовой точки в новую
не попадают. Одинаковые байты пакуются один раз, восстановление создаёт независимые
файлы, а не общие hardlink. Восстановленные реестры — архив, не новый главный реестр.

Публикация повторяема после сбоя: неизменные архивные объекты переиспользуются,
неподтверждённая загрузка остаётся `.partial`. Не удалять такие файлы автоматически
по общему шаблону. Чужой READY или объект с неверным хешем не перезаписывается.
Завершение подтверждается READY.json и локальным published.json. Объекты общие
для нескольких точек; нельзя удалять их по принадлежности одной старой точке.

Это механизм хранения, не расчётный запускатель и не фоновый сервис. Наличие
READY означает целостность копии, а не отсутствие ошибок в модели. Основной
реестр обновляется только по rules/common/history.md с блокировкой.

После первого полного переноса не требуется каждый раз архивировать всю историю.
Код сохранять отдельной точкой; для завершённого расчётного этапа можно создать
отдельную выборку новых каталогов и метаданных. В её config записать ссылку
`parent_checkpoint` на исходную точку и в журнале продолжения — порядок слоёв.
Такой слой не является полной самостоятельной копией рабочего каталога.
Восстанавливать его в отдельную пустую папку, затем применять только явно
описанные новые/заменяемые пути с резервной копией прежних метаданных. Скрипт
restore сам не накладывает слои и не удаляет файлы живой рабочей папки.
Для полного самодостаточного снимка использовать ту же выборку и --baseline:
в этом режиме список файлов полный, они повторно хешируются, новые архивы
содержат только изменённые файлы. Выбирать режим по фактической зависимости этапа.

Первичный перенос содержит историческую исследовательскую рабочую папку.
Зафиксированные в старых журналах абсолютные пути сохраняются как происхождение;
на новом ПК пути исполнения подбираются заново. Navisworks/.NET/Node/Python и
лицензия Autodesk не поставляются копированием чужой установки. Зависимости
описаны в development/README.md и файле передачи состояния. Revit не нужен.
