# Импорт NWD по физическим фрагментам

С 0.1.23 большие массивы метаданных и дерева проверяются потоково, без
загрузки полного JSON в память. Входная полнота и контроль байтов сохранены.

Дополнительный `nwd_fragment_matrices.bin` содержит на фрагмент 136 байт:
int32 geometry_index, int32 fragment_index, затем 16 little-endian float64.
Manifest объявляет literal_matrix_file и literal_matrix_sha256. Индексы и
порядок обязаны совпадать со всеми fragmentRecords. При наличии этого файла
матрица JSON служит отображению: сериализатор .NET может округлить её.
Расчёт использует буквальную двоичную матрицу и проверяет воспроизведение
каждой мировой вершины. Нельзя повторно преобразовать мировые треугольники.
Необъявленный двоичный файл или его лишние/недостающие записи отвергаются.

На Windows с установленным Navisworks Manage собрать engine/NwdFragmentProbe.cs
командой `scripts/build-nwd-probe.py --runtime <каталог Navisworks> --output <новый каталог>`.
Сборка сохраняет хеши исходника, EXE, компилятора и библиотек.
Перед запуском задать NAVISWORKS_RUNTIME тем же каталогом установленного продукта.
EXE принимает ровно два аргумента: NWD и новый, ещё не существующий каталог выгрузки.
Не использовать старый EXE из другого выпуска, даже если рядом обновлённый исходник.

Экспорт содержит nwd_geometry.json, nwd_triangles.bin, nwd_sets.json,
all_nodes.json и nwd_export_manifest.json. Треугольники — little-endian float64,
72 байта на треугольник, координаты уже преобразованы в мировую систему Navisworks.
local_to_world сохраняет исходную матрицу; повторно применять её к треугольникам нельзя.
Единицы берутся из manifest.models, отдельно от матрицы. Пустая геометрия
сохраняет семантику в all_nodes.json и не становится доказательством материала.

COM Fragments() на некоторых инстансах возвращает фрагменты других экземпляров.
Импортёр сверяет ToModelItem(frag.path) с текущим узлом перед извлечением треугольников.
Число пропусков хранится в skipped_foreign_instance_fragments. Чужая геометрия
не получает ID текущего элемента. Материал берётся со свойств фактического
фрагмента; родительская сводка материалов не используется.

`scripts/inspect-nwd-export.py --config <run.json> --export <каталог> --output <новая папка>`
проверяет входную структуру и выполняет отбор. Проектный словарь материалов
и подтверждённые назначения должны иметь записанное основание. Для подтверждения
пользователя verified_fragment_assignments содержит fragment_id, input_nwd_sha256,
fragment_metadata_sha256 (policy.digest исходной записи из fragment_inventory.json),
values (только material/construction_method/role) и evidence:
type=user_confirmation, statement, registry_scope. Не переиспользовать такое
подтверждение для изменённого NWD или другого проекта.

Успех этого этапа не сертифицирует замкнутость/объём исходных тел, разности,
измерения, группировку или отчёты. Открытые и неманифолдные поверхности,
окрашенные исходные грани и обратные преобразования требуют геометрического
аудита. Достраивать отсутствующие грани автоматическим repair нельзя.

Начиная с 0.1.22 новый probe также пишет `nwd_local_triangles.bin` в том же
порядке и диапазонах, что и мировой файл. В нём исходные координаты callback
до применения матрицы. Manifest содержит фиксированное имя и SHA256.
`validate_export` привязывает этот файл к приёмке и требует буквального
воспроизведения каждой мировой вершины прежней формулой. Нельзя повторно
применять матрицу к уже мировому файлу. Старая схема 2 без дополнительного
локального файла поддержана, но у неё нет этого точного исходного справочника.

`nwd_local_coordinates.exact_affine_point` считает исходное аффинное
преобразование рационально. Разница с округлённым мировым callback
исследуется отдельно. Один лишь численный предел не позволяет удалить
реальное отверстие: нужны исходные грани, топология и геометрическое
доказательство конкретного случая. Ни локальный файл, ни его успешная
валидация не подтверждают полный объём, отверстия, БЕП или готовность отчётов.

`polygon_raster.paint_polygons` использует прозрачную маску материальных
полигонов. Отверстия очередного полигона не закрашиваются белым поверх
уже нарисованного общего монолита. Этот блок оформляет предоставленную
геометрию; он не создаёт геометрию замечания.
