# Запуск проверки монолита: вам и другому сотруднику

Для запуска из Cursor см. [CURSOR_START.md](CURSOR_START.md).
Упоминаемый ниже `new-check.ps1` открывает Codex через `codex://`;
в Cursor новый чат с данными проверки открывают вручную.

Версия инструкции 0.1.2. Общие правила: KPLN_MonolithMatchCheckRules.

## 1. Что означает «автоматическое сообщение»

Предусмотрен запуск нового чата с готовой формой **в поле ввода**. Это черновик
пользовательского запроса, а не уже отправленный ответ ассистента. Запускатель
использует поддерживаемый `codex://new?prompt=...&path=...`, не внутреннюю БД
приложения. Он ничего не отправляет и не запускает расчёт до вашего действия.
Обычный пустой чат при открытии сам по себе форму не получает.
Источник: https://learn.chatgpt.com/docs/reference/commands

## 2. Подключение — один раз на каждом компьютере

1. Убедиться, что доступны папка общих правил и исходный NWD. Диск X должен
   указывать на общий сервер компании. Для файлов вне локального проекта Codex
   может запросить разрешение; доступ определяется правами данного сотрудника.
2. Открыть PowerShell обычным пользователем и выполнить:

```powershell
& 'X:\BIM\5_Scripts\Git_Repo_KPLN\KPLN_MonolithMatchCheckRules\scripts\install-skill.ps1'
```

3. Ожидаемые сообщения: `Installed skill` и `Shared rules`. Установщик сохраняет
   прежнюю установку, если она была. В версии 0.1.1 добавлены метаданные, поэтому
   после 0.1.0 установщик нужно выполнить ещё раз. Общие файлы правил он не копирует
   в личный скилл, а записывает ссылку на общую папку.
4. Если навык не появился в новом чате, перезапустить Codex. Не менять политику
   безопасности PowerShell глобально при ошибке запуска: передать текст ошибки
   BIM-менеджеру/ИТ. Установка не требует запуска приложения от администратора.

Официальное описание навыков: https://learn.chatgpt.com/docs/build-skills

## 3. Новая проверка в существующем проекте

Нужна локальная рабочая папка проекта. У инициатора этой разработки она такая:

```powershell
& 'X:\BIM\5_Scripts\Git_Repo_KPLN\KPLN_MonolithMatchCheckRules\scripts\new-check.ps1' -Workspace 'C:\Users\spetrov\Documents\ChatGPT\Проверки_Совпадение монолита'
```

Команда откроет новый чат с указанной рабочей папкой и формой в поле ввода.
Для другого объекта использовать новый каталог результатов внутри неё;
не перезаписывать прежние runs. Сам выбор папки не переносит историю беседы:
методика берётся из скилла, история замечаний — из реестра.

Если создаёте чат обычной кнопкой, можно отправить одну строку:
`Используй $kpln-monolith-match-check. Начать новую проверку монолита.`
Тогда ассистент в ответ запросит только недостающие данные.

## 4. Какие поля заполнить

| Поле | Что указать |
|---|---|
| Проект | Название объекта; при повторной проверке прежний ключ реестра |
| Стадия | ПД или РД, обязательно явно |
| Корпус/секция | Конкретная область; для корпуса целиком так и написать |
| NWD | Полный доступный путь к новой версии модели |
| Тип проверки | Первичная или контрольная |
| Планы/разрезы | Для рабочей ПД — документы, задающие область проверки |
| Результат | Корневая папка отчётов объекта; подпапка итерации создаётся автоматически |
| Вариант | Фулл или Лайт; для Лайт перечислить дополнительные исключения |

Именование: `2026.10.23_Монолит_Фулл_К2С14`. При необходимости в конце указать
этажи, например `_Этажи01-05`. Если папка занята — `_02`, `_03`; старую не менять.
Подробности: ../rules/common/result-folders.md.

Пути можно вставлять в сообщение или прикладывать файлы. Для ПД указать
проверяемые виды; геометрическую привязку агент извлечёт, если она достоверна,
иначе уточнит границы/отметки/глубину. РД проверяется целиком.
Поля с <...> заменить, ненужные удалить. Пример полностью заполненного текста
не делает пробную модель настоящим источником — данные должны быть фактическими.

Допуск 50 мм на РД не включается от одного выбора стадии. При необходимости
добавить: «Эта проверка выполняется для здания со смонтированными монолитными
конструкциями». По умолчанию используются обычные допуски стадии.

После заполнения нажать «Отправить». Агент проверит исходные данные, выберет
реестр, сохранит версию правил и подготовит запуск. Если выявлены недостающие
данные/средства извлечения геометрии, он сообщит их, не выдавая результат за полный.

## 5. Контрольная проверка

Передать новую версию NWD и тот же проект/стадию/корпус/секцию; указать контрольную
проверку и корень отчётов. Новая подпапка создаётся по дате, варианту и области.
Не создавать отдельный реестр под дату/сотрудника и не обнулять номера.
Новые результаты сохраняются в новой папке, номера и первая дата — из общего
реестра. Для К2С14: sgrvn / PD / K2 / S14. Новую папку результатов выбирать можно.

Для рабочей ПД актуальные планы/разрезы могут ограничить область. Старое замечание
вне области не становится устранённым. Режим полного теста ПД использовать только
при явном поручении. Для другого корпуса/стадии действует отдельная история.

## 6. Если запускает другой сотрудник

Он выполняет установку на своём ПК, затем ту же команду new-check.ps1 со СВОЕЙ
локальной папкой, например `C:\BIM\MonolithChecks` (заранее создать её).
Нельзя использовать путь профиля spetrov как обязательный для всех.
Все используют общую папку правил и общее хранилище реестров. При локальном
Git-клоне задаётся общий state_root — личная копия реестра не является основной.
У сотрудника должны быть доступ к NWD и рабочий способ его геометрической
выгрузки. Доступ к чату коллеги для продолжения истории замечаний не требуется.

Параллельные расчёты возможны, но обновление одного реестра защищено блокировкой
и проверкой предыдущей версии. При конфликте сначала согласовать с новым состоянием,
не перезаписывать изменения коллеги. Проверка между двумя физическими ПК пока
не выполнена; не считать успешные локальные тесты подтверждением настроек SMB.

## 7. Границы готовности

Пакет — правила, входной контроль, история и подготовка запуска. Универсальный
полный геометрический движок нового NWD пока не упакован. Первый другой объект
требует подключения/проверки расчётных этапов. Запускатель чата не означает
«модель проверена», а prepare-run не вычисляет несовпадения. Ожидаемые два
отчёта выдаются только после фактического расчёта и всех обязательных проверок.
См. ../rules/common/readiness.md.

Реестр К2С14 перенесён в общую папку с согласия владельца. Его первичная локальная
копия сохранена как архивная, есть резервная копия и migration_receipt.json.
