# Проверка из Cursor

Работа предполагает локальный Cursor на Windows-компьютере сотрудника
с доступом к общим правилам, NWD, папке результатов, общему реестру и
подходящему Navisworks. Облачная сессия сама по себе не получает диски X/Y
и локальную установку Navisworks.

## Подключение

Можно передать полный путь к общему SKILL.md в сообщении Agent и поручить
прочитать его до расчёта. Для постоянного подключения выполнить один раз:

```powershell
& 'X:\BIM\5_Scripts\Git_Repo_KPLN\KPLN_MonolithMatchCheckRules\scripts\install-skill.ps1'
```

Существующий установщик по умолчанию размещает короткий скилл в
`~/.agents/skills/kpln-monolith-match-check` и записывает `rules-root.txt`
с адресом общих правил. Cursor поддерживает этот каталог, а также
`~/.cursor/skills`. При необходимости целевой каталог можно явно передать
через `-SkillDirectory`. Следует поддерживать одну установку навыка.
Наличие установленного скилла проверить в новом чате Cursor.

Источники: [Cursor Skills](https://cursor.com/docs/skills),
[Cursor Help: Skills](https://cursor.com/help/customization/skills).

Скрипт `new-check.ps1` использует `codex://` и предназначен для Codex.
Для Cursor он не нужен: сотрудник открывает свою локальную рабочую папку
и новый чат Agent вручную. Используется свой профиль Windows, не путь
инициатора разработки.

## Данные первого сообщения

```text
Сначала прочитай:
X:\BIM\5_Scripts\Git_Repo_KPLN\KPLN_MonolithMatchCheckRules\skills\kpln-monolith-match-check\SKILL.md

Проверь совпадение монолита АР/КР.
Проект: <точное название/ключ существующего реестра>.
Стадия: <ПД или РД>.
Корпус/секция: <область проверки>.
NWD: <доступный полный путь>.
Проверка: <первичная или контрольная>.
Корневая папка отчётов: <полный путь>.
Для рабочей ПД: <планы/разрезы и область>.
Используй общий реестр и новую отдельную папку результатов.
Нужны оба полных отчёта с одинаковыми номерами.
```

Для существующего СГМ использовать зарегистрированное название
`Сочи гостиница Москва`: проектное правило 200/300 мм выбирается по нему,
а не угадывается из имени файла. Для СГРВН сохранять ключи общего реестра.

Общие правила обновляются в одной сетевой папке. Каждый расчёт сохраняет
неизменный снимок; обновление X не пересчитывает начатый выпуск автоматически.
Общий реестр используется всеми сотрудниками; личные параллельные копии
истории не создавать.

## Граница готовности

Ссылка на скилл и данные позволяют начать работу по общей методике.
Для готовых отчётов дополнительно нужен принятый переносимый расчётный процесс
на ПК сотрудника. Версия скилла и модульные тесты не подтверждают его готовность.
До независимого полного пробного запуска см. [readiness.md](../rules/common/readiness.md).
