# Общий реестр и итерации

Ключ: project / stage / building_id / section_id. Для целого корпуса без секций
section_id=null; для отдельной секции без корпуса building_id=null. Это разные
области: проверка целого корпуса не закрывает автоматически реестр секции.
Текущий ключ: sgrvn / PD / K2 / S14 (СГРВН К2С14).
Существующий реестр К2С14 перенесён с явного разрешения владельца:
local/shared-state/registries/sgrvn/PD/K2/S14/registry.json.
839 замечаний, 1431 физических случая; номера, даты, статусы и группы сохранены.
Локальная копия в проекте разработки помечена superseded_by и не принимает
новые итерации. Свидетельство переноса находится рядом: migration_receipt.json.

Общий state_root по умолчанию: local/shared-state в сетевой папке правил.
При личных checkout задавать общий state_root явно. Копирование реестра на
другой компьютер не делает его новым независимым источником истины.

Сохранять номера групп/конфликтов/меток, первую подтверждённую дату, наблюдения
и статусы. Новое / неотработанное / возобновлено; вне объёма перепроверки —
не проверялось. Устранено лишь при доказанной полной проверке области теми же
правилами. Новые допуски сами по себе не доказывают физического устранения.
При смене правил объяснять различие в журнале, не переиспользовать старый номер.

geometry_identity.bind_geometry привязывает идентичность к содержимому
подтверждённых сечений/mesh-файлов. ID и габариты недостаточны. Изменившаяся
геометрия требует однозначного сертификата соответствия. Разделение/слияние
групп требует явной преемственности; текущий модуль останавливает неоднозначность.
Номера не зависят от текущей сортировки и одинаковы в обоих типах отчётов.

После геометрического расчёта:
1. update_history.py prepare REGISTRY ENTRIES COVERAGE OUTPUT RUN_ID DATE
   (при необходимости --certificates FILE) создаёт canonical_entries.json,
   registry_pending.json и transaction.json, не перезаписывая общий реестр.
2. Построить оба отчёта из canonical_entries.json и проверить оба. Протоколы
   содержат passed, canonical_entries_sha256 и artifact_hashes с реальными файлами.
3. update_history.py commit OUTPUT PLUGIN_RECEIPT COORDINATOR_RECEIPT.
   Эксклюзивный lock и сравнение предыдущего хеша защищают от потерянных изменений.
   Если коллега уже обновил реестр, повторить согласование с новой версией;
   не перезаписывать её силой. Lock после сбоя не удалять без проверки владельца.

Первый реестр создавать из полностью проверенного выпуска через history.seed;
публиковать только после проверки обоих отчётов, с эксклюзивным созданием и
проверкой отсутствия другого реестра. Первый выпуск К2С14 — 22.10.2026,
это первая доказанная дата данного реестра, не выдуманная дата раннего обнаружения.
Сетевую блокировку между двумя разными ПК ещё требуется принять на рабочем SMB.
