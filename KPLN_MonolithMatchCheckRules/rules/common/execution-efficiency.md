# Организация расчёта и сокращение повторной работы

Общие принципы для новых и контрольных проверок всех проектов. Они задают
организацию работы; фактическая поддержка кэша и локального пересчёта должна
быть подтверждена реализацией движка. Полнота проверки и правила допуска
сохраняются. Время новой модели нельзя обещать по одному прошлому запуску.

## 1. Одна принятая расчётная цепочка

Использовать закреплённую версию этапов: импорт и входной контроль → геометрия
и измерения → проектные правила/БЕП → физическая группировка и история → оба
отчёта → приёмка. Явно сохранять состояние и результаты каждого этапа.

Разработку нового алгоритма отделять от обычного выпуска: воспроизвести
проблему отдельно, проверить исправление, затем подключить новую версию
с учётом зависимостей. Отклонённые попытки не заменяют принятые результаты.
Неразобранная часть не блокирует независимую работу над остальной моделью,
но остаётся явным препятствием окончательному полному выпуску.

## 2. Принятые промежуточные результаты и зависимости

Сохранять принятые результаты с хешами исходных данных, потреблённых параметров,
версий алгоритмов и реальных выходных файлов. Возобновление допустимо после
проверки этих хешей и полноты требуемой области. ID и габариты не доказывают,
что геометрия не изменилась. Не хешировать один неизменный большой файл заново
внутри каждого цикла по его записям; вычислить отпечаток один раз за этап.

Новый NWD требует нового импорта/инвентаризации. Повторно проверить единицы,
преобразования, материалы, источники и вычисленные наборы «Скрыть».
После этого переиспользовать только независимо доказанные неизменные части.
Пересчитывать изменённые части вместе со всеми зависимыми сборками, связями
АР/КР, соседними границами и областями поиска. Неизменность одного владельца
не означает неизменность отверстия, образованного несколькими владельцами.

Если движок не умеет доказать безопасную область локального пересчёта,
пересчитать необходимую более широкую область. Изменение системы координат
или глобальных условий может потребовать полного пересчёта.

## 3. Локальные сборки и устранение дублирующей работы

Использовать пространственные индексы и фактическую связность материала для
поиска всех элементов локальной сборки. Проверять отверстие по совокупности
материала, включая соседние стены, плиты, балки и иные тела.
Границу локальной области расширять, пока достаточность её охвата не доказана.

Повторные сечения/подзадачи с одинаковыми доказанными входами рассчитывать
один раз, сохраняя связь всех исходных наблюдений с результатом.
Предварительный отбор должен сохранять все потенциальные физические случаи.
Не заменять им доказательство пустоты, полноты, отсутствия или примыкания;
не удалять малые отверстия, сложные контуры и численные неопределённости.

## 4. Геометрия, решения и оформление — отдельные этапы

Оба отчёта строить из одной принятой канонической иерархии. Изменение поиска,
оформления, HTML, изображений или разбиения ZIP само по себе не запускает
повторное вычисление неизменной геометрии и не присваивает новые номера.

Изменение допуска, назначения, БЕП или проектного правила требует повторного
решения и всех зависимых измерений/связей/группировки; это не изменение только
оформления. Исходные поверхности допускается переиспользовать лишь при
совпадении их собственных зависимостей. Итоговые протоколы связываются с
текущим профилем и исходным NWD; старый успешный протокол не переименовывать
в доказательство нового расчёта.

## 5. Измерение времени и границы готовности

По этапам записывать фактическое время, объём входов, количество повторно
принятых результатов, причины недействительности кэша и оставшиеся случаи.
Оптимизировать этапы, которые занимают основное измеренное время.
Оценку длительности давать после контрольных прогонов нового и повторного NWD.

Параллельный запуск независимых вычислительных подзадач ограничивать доступной
памятью/CPU и требованиями приложения; не размножать тяжёлые одинаковые операции.
Общий реестр изменять только штатной защищённой транзакцией после обоих отчётов.

Эти требования не объявляют существующий движок полностью переносимым или
все перечисленные оптимизации уже реализованными. При отсутствии нужной
реализации явно сообщить ограничение, см. [readiness.md](readiness.md).
