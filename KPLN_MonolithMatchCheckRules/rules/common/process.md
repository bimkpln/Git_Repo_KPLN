# Порядок проверки

Работать локально с проверенными контрольными точками на X по
[local-first.md](local-first.md). Техническую адаптацию и выбор применимых
доработок выполнять самостоятельно, фиксируя их в служебном журнале.

Для новых и контрольных проверок применять
[общие принципы организации и ускорения расчёта](execution-efficiency.md).
Поддержку конкретной оптимизации подтверждать реализацией и проверкой движка.
Если при проверке требуются доработки, применять
[отдельное сохранение предложений сотрудников](contributions.md): рабочая копия,
исходная версия, diff/файлы, доказательства и тесты. Обычный запуск не обновляет
общую версию. Принятый профиль текущего расчёта не заменять незаметно.

1. Уточнить только недостающие: проект, ПД/РД, корпус/секцию, АР/КР источники,
   NWD, первичная/контрольная, каталог вывода. Для рабочей ПД получить планы и
   разрезы с границами/глубинами/координатной привязкой. Полный ПД допустим лишь
   по явному разрешению тестового полного запуска. РД — вся модель.
   Каталог пользователя — корень отчётов объекта. На каждый новый запуск создать
   подпапку по [result-folders.md](result-folders.md): дата_Монолит_Фулл/Лайт_область.
   Для Лайт запросить только недостающий точный список дополнительных исключений.
2. Выбрать общий реестр через registry_scope.py; найти предыдущий выпуск.
   Для существующего объекта не создавать параллельную историю в личной папке.
3. Выполнить prepare-run.py: снимок версии/файлов правил, хеш исходного NWD,
   единицы, проектный профиль, автор и время. Секреты и учётные данные не записывать.
4. Проверить реальную доступность импорта NWD. Импорт должен сохранить источники,
   Revit ID экземпляров, преобразования, материал каждого mesh-фрагмента,
   уровни АР, сетку осей и вычисленное членство наборов папки «Скрыть» рекурсивно.
   Не считать видимость в текущем виде эквивалентом членства поисковых наборов.
5. Материальный входной контроль preflight.py; неизвестные назначения разобрать
   по свойствам и источнику. Отделка, металл, кладка, сборный бетон исключаются
   по доказательствам. Пол/окно/дверь как изделие не монолит; реальная пустота
   в бетоне остаётся предметом проверки. Словарь материалов только проектный.
6. Сравнение по geometry.md и выбранному профилю, включая явно заданные
   проектные правила `rules/projects` для точного ключа проекта. Геометрический движок обязан
   подтвердить контракт validate_engine_receipt; декларация без расчёта не доказательство.
7. Физические замечания, типовые группы, согласование с историей; один
   canonical_entries.json для обоих отчётов. Зафиксировать исключения и основание.
8. Выпустить оба комплекта только после проверки полноты, ID/координат, геометрии,
   счётчиков, импорта HTML, изображений и интерфейса. Обновить реестр транзакцией.
   Непроверенные случаи не удалять ради «без вопросов»: сохранять диагностику
   отдельно, завершить разбор до окончательного выпуска.

Кэш: хеш геометрии, преобразований, материалов, наборов, профиля, области и
версии алгоритма. Новая модель требует нового импорта/инвентаризации. Изменение
отделённого оформления не требует заново считать неизменную доказанную геометрию.
