# Папки результатов каждой проверки

Пользователь задаёт корневую папку отчётов объекта, например:
Y:/Общественные здания/Сочи гостиница Москва/10.Стадия_Р/BIM/2.Отчеты_о_пересечениях_html
Для каждого нового запуска создать отдельную подпапку:
`ГГГГ.ММ.ДД_Монолит_Фулл|Лайт_КорпусСекция[_Этажи]`.

Примеры: `2026.10.07_Монолит_Фулл_Блок1`,
`2026.10.23_Монолит_Лайт_К2С14`,
`2026.10.23_Монолит_Фулл_К2С14_Этажи01-05`.
Дата — начало выполнения данной проверки по Москве; если расчёт продолжается
на следующий день, исходная папка/дата сохраняются. Продолжение прерванного
запуска использует ту же папку, новая проверка — новую.

Фулл = полный согласованный состав проверки в выбранной области с обычными
допусками/исключениями БЕП. Стандартные наборы «Скрыть» и отбор монолита не
превращают проверку в Лайт. Лайт = дополнительные явно заданные исключения,
например без инженерных отверстий или без определённых конструкций.
Для Лайт обязательно записать точный список в run.json и журнал выпуска;
по одному слову «Лайт» не угадывать, что исключать.
Ограничение этажами/видами и состав исключений — разные параметры.
Обозначения области брать у пользователя/из модели, не навязывать формат Блок.

Если имя занято, добавить `_02`, `_03` и далее. Создание папки атомарное,
прежние результаты не перезаписывать. Фулл/Лайт не создают новые реестры:
общий реестр прежний проект/стадия/корпус/секция. Изменение исключений меняет
профиль проверки; исключённые старые замечания не считать устранёнными.

В папке запуска — оба отчёта, ресурсы и служебные материалы (по подпапкам).
Реестр хранится отдельно в общем state_root. Для подготовки использовать
`prepare-run.py --results-root ROOT ...`, в конфигурации `result_scope_label`,
`check_variant: full|lite`, `additional_exclusions: [...]`.
Старый --output остаётся явным выбором точной папки для специальных сценариев.
Подготовка имён/профиля не означает, что геометрический движок уже применил
исключения: обязательный контракт требует отдельно подтвердить их исполнение.
