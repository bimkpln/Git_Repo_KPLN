# KPLN_RevitMcpBridge

Отдельный проект Visual Studio для связи Revit 2020/2023/2024/2026 с Codex.
Загружается **только через KPLN_Loader**: `KPLN_RevitMcpBridge.Module`
реализует `KPLN_Loader.Common.IExternalModule.Execute/Close`.
Мост **выключен после каждого запуска Revit**. Загрузка модуля создаёт только
кнопку: HTTP-порт не открывается и сессия для Codex не публикуется.
Нажатие **KPLN → BIM → Codex Мост** только открывает окно состояния.
Если мост остановлен, доступно действие **«Запустить мост»**; если работает —
**«Остановить мост»**. После действия команда завершается, окно не открывается
повторно. Актуальное состояние видно при следующем нажатии кнопки на ленте.
Закрытие окна не меняет подключение. Повторное открытие после остановки
не запускает мост; состояние не сохраняется между запусками Revit.
Кнопка добавляется на первом Idling после загрузки остальных модулей, чтобы
не конфликтовать с созданием панели BIM в KPLN_BIMTools_Ribbon.

## Иконки кнопок

Схема соответствует `00_KPLN_Templates/KPLN_CSharp_Template`: общий метод
`AddPushButtonDataInPanel` принимает базовое имя иконки (`mcpBridge`) и получает
изображения 16/32 через `KPLN_Loader.Application.GetBtnImage_ByTheme`.
В `Imagens` хранятся четыре PNG: `mcpBridge16.png`, `mcpBridge32.png` для светлой
темы и `mcpBridge16_dark.png`, `mcpBridge32_dark.png` для тёмной. Все четыре файла
подключены в `.csproj` как **Resource** и встраиваются в DLL; копировать PNG
рядом с DLL не нужно. Loader читает их через WPF pack URI.

Цветовая схема: стандартная светлая тема — чёрный знак; вариант `_dark` —
нейтральный светло-серый знак с тонким графитовым контуром. Светлая часть видна
на тёмном фоне, контур отделяет знак от светлого серого. Фон PNG прозрачный.
Loader выбирает ресурс по `UIThemeManager.CurrentTheme`, а не по цвету фона
вида/модели; вариант `_dark` рассчитан также на серые поверхности интерфейса.

Сборка выполняется в Visual Studio либо `scripts/build.ps1`, который находит
MSBuild.exe из Visual Studio / Build Tools (можно задать `-MSBuildPath`).
`dotnet msbuild` для основного проекта запрещён: в этом классическом проекте
он пропускает упаковку WPF Resource и создаёт DLL без иконок.

В Revit 2024 кнопка регистрируется в `KPLNButtonsForImageReverse`: при смене
темы Loader обновляет обе иконки. В конфигурациях Revit 2020/2023 эта регистрация
исключена директивой компиляции, как в шаблоне. Для новой кнопки нужно добавить
аналогичный комплект `{имя}16.png`, `{имя}32.png`, `{имя}16_dark.png`,
`{имя}32_dark.png` как Resource и передать только базовое имя в общий метод.

## Архитектура

### Печать без окна через KPLN_Publication (мост 1.0.10)

`print_revit_sheets_pdf(document_id, expected_revision, settings, dry_run=True)`
вызывает публичный `KPLN_Publication.BatchPrintService.PrintAllSheets` (контракт v1,
Publication 1.4.8). Мост не содержит реализации принтера и не загружает DLL по
переданному пути: используется только уже загруженный Loader модуль Publication.

Настройки — поля `YayPrintSettings`, по умолчанию: PDFCreator, все листы текущей
модели, `C:\PDF_Print`, `<Номер листа>_<Имя листа>.pdf`, VectorProcessing, Color,
Medium, обновление спецификаций. DWG, бумага, объединение, исключение границ и
исключения цветов не поддерживаются этим headless-контрактом и отклоняются явно.
Режим с обычным окном сохраняет прежние возможности.

Dry run проверяет весь комплект, имена, принтер, профиль и доступность форматов.
Фактическая печать использует уникальную подпапку запуска; файлы не перезаписываются.
Нужен один основной штамп на листе и установленный формат бумаги. Новый формат
автоматически не создаётся. Профиль 0 PDFCreator должен быть явно привязан к этому
принтеру. Профиль временно переводится в автосохранение, действия профиля отключаются;
исходные значения восстанавливаются. Не печатайте другие задания в PDFCreator во
время запуска. Обновление спецификаций и настройки модели заключены в откатываемую
TransactionGroup; сохранение/синхронизация модели не выполняются.

В ответе и `manifest.json` перечислены все листы со статусами planned/submitted/
exported/failed, путями и SHA256 готовых PDF. Заголовок и завершение PDF проверяются;
визуальный контроль и число страниц проверяются отдельно. При первом сбое цикл
останавливается; неотправленные листы остаются planned. `complete` — только при
готовности всего комплекта без ошибок восстановления. При `outcome_pending` читать
`get_revit_operation`, не повторять команду. При таймауте PDF задание может остаться
в очереди принтера: проверить её вручную до следующего запуска.

Для загрузки обновлений требуется полный перезапуск Revit и запуск моста его кнопкой.
Остановить/запустить HTTP-мост недостаточно для замены загруженных DLL.

```text
Codex → MCP stdio (Python FastMCP) → HTTP 127.0.0.1
  → KPLN_RevitMcpBridge.dll → потокобезопасная очередь → ExternalEvent → Revit API

KPLN_RevitRules ← тонкий навык Codex: правила, проектные решения, записи анализа
KPLN_JobCandidateModelCheckRules ← тонкий навык проверки: критерии и доказательства
```

Как в KPLN_NavisMcpBridge / KPLN_NavisClashRules, транспорт и Revit API
отделены от инженерных решений. C# извлекает данные и выполняет транзакции,
Python предоставляет MCP-инструменты. Правила не компилируются в DLL и
не встроены в MCP-сервер. Логика нормализации здесь проста: геометрия в мм,
Double-параметры сохраняют внутренние единицы Revit с указанием типа величины.

## Сборка и KPLN_Loader

Открыть `KPLN_RevitMcpBridge.sln`. Конфигурации `Debug2020/2023/2024/2026` и
`Revit2020/2023/2024/2026`, x64, C# 7.3. Для Revit 2020/2023/2024 используется .NET Framework 4.8; для 2026 — .NET 8 (net8.0-windows7.0), как в BIMTools.
Нужны установленные Revit API и DLL вашего Loader по пути
`X:\BIM\5_Scripts\SetupFiles\Revit\1.Common\KPLN\<год>\KPLN_Loader\KPLN_Loader.dll`.
Пути переопределяются свойствами MSBuild `RevitApiRoot` и `LoaderRoot`; для Loader 2026 — `KPLNLoaderPath`. Конфигурации 2026 подключают общий `..\build\KPLN.Revit2026.props`, требуют .NET SDK 8 или новее и используют System.Text.Json без дополнительных DLL.

Конфигурации проекта объявлены явными парами `Debug2023|x64` и т. п.;
платформы Any CPU нет. F5 запускает `Revit.exe` выбранного года как внешнюю
программу. После изменения проекта согласиться на Reload в Visual Studio
или заново открыть solution, затем выбрать нужную конфигурацию и x64.

При Debug-сборке DLL и PDB сначала создаются в `bin\Debug\<год>`, затем
копируются в `bin\<год>`, откуда их забирает зарегистрированный Loader.
Это заменяет сборку этого года в папке публикации на отладочную. Таким образом
Loader загружает свежую DLL с символами, а не старую release-сборку. Папку
можно переопределить через `LoaderModuleRoot`, копирование отключить через
`/p:CopyDebugToLoader=false`. Повторная Revit-сборка возвращает release DLL.
Если DLL уже загружена в открытый Revit, для проверки новой сборки перезапустить
этот экземпляр или запускать новый через F5; Attach к старому процессу DLL не обновляет.

```powershell
./scripts/build.ps1
# Только Revit 2026:
./scripts/build.ps1 -RevitVersion 2026
```

Release-сборки локального проекта лежат в `bin\2020`, `bin\2023`, `bin\2024`, `bin\2026`. В общем репозитории сохраняется принятый путь публикации на Z:.
В менеджере БД KPLN_Loader создать запись:

| Поле | Значение |
|---|---|
| Name | KPLN_RevitMcpBridge |
| Path | полный путь к `KPLN_RevitMcpBridge\bin` |
| IsEnabled | True |
| IsLibraryModule | False |
| IsDebugMode | по принятому порядку тестовой публикации |

Назначить модуль нужным подразделениям в `ModulesMatrix`. Loader фильтрует
модули по этой матрице — одной записи Modules недостаточно. Для обычного
модуля `CopyModule` выбирает `Path\<год>`, даже у пользователя в debug-режиме;
папка `Debug\<год>` используется Loader только для библиотек. Поэтому запись
указывает на release `bin`, либо на специально подготовленную папку публикации
с подпапками годов. DLL Loader/Revit API рядом с модулем не копируются.

При установке в ExtraNet скопировать DLL нужного года в
`<папка KPLN_Loader>\Modules\KPLN_RevitMcpBridge\`.
Самостоятельный `.addin` для этого проекта не нужен. Изменять код Loader не нужно.
Перезапустить Revit после регистрации/обновления модуля; уже открытый процесс
новую DLL сам не подхватит. Регистрация в общей БД не производится скриптами
этого проекта: область назначения в ModulesMatrix выбирается в менеджере БД.

## Подключение Codex

Создать отдельное Python-окружение (3.11+ для установщика), затем:

```powershell
python -m venv .venv
./.venv/Scripts/python.exe -m pip install -r server/requirements.txt
./.venv/Scripts/python.exe scripts/install_codex.py --python .venv/Scripts/python.exe
../KPLN_RevitRules/scripts/install-skill.ps1
```

Установщик добавляет `[mcp_servers.revit]` в конфигурацию Codex с резервной
копией, сохраняет остальные серверы и не меняет пользовательскую политику
подтверждений. Если revit уже настроен иначе, отказывается его перезаписывать.
Перезапустить MCP/открыть новую задачу, чтобы загрузились инструменты и навык.
Формат подключения: [официальная документация Codex MCP](https://developers.openai.com/codex/mcp).

После выбора «Запустить мост» в окне состояния мост выбирает свободный порт 18765–18784 и пишет описание сессии в
`%LOCALAPPDATA%\KPLN\RevitMcpBridge\sessions\<session_id>.json`.
Там хранится локальный ключ; его не надо копировать в репозиторий или переписку.
MCP автоматически находит сессии. При нескольких открытых Revit обязательно
указать session_id. Все HTTP-запросы требуют токен; Origin и перенаправления
не поддерживаются. Если HttpListener сообщает Access denied, администратор
должен разрешить выбранный localhost URL через Windows HTTP URL ACL; ошибка
видна по кнопке моста. Правила брандмауэра для внешнего доступа не нужны.

## Инструменты

| Область | Инструменты |
|---|---|
| Сессии и диагностика | list_revit_sessions, get_revit_bridge_health, get_revit_operation |
| Документ | get_revit_documents, get_revit_context |
| Элементы | get_revit_selection, get_revit_categories, find_revit_elements, get_revit_elements |
| Виды и связи | get_revit_views, get_revit_links |
| Семейства | get_revit_families, get_revit_family_types, get_revit_family_document |
| Действия | select_revit_elements, set_revit_parameters, create_revit_family_types, set_revit_family_type_parameters |

Чтение элементов работает в активном документе. `document_id` проверяется
при каждом запросе, чтобы переключение файла в Revit не перенаправило команду.
Страницы возвращают `next_offset`; сравнивать их следует при одной `revision`.
`get_revit_context` возвращает документ и revision внутри result.document.
Другие команды возвращают document_id и revision на верхнем уровне ответа.

Для записи передать `document_id`, `expected_revision` и до 200 updates:
`element_unique_id`, `parameter_id`, `expected_value`, `value`; для Double также
`value_units: "revit_internal"`. dry_run по умолчанию true. План проверяет
параметры без транзакции; реальные ограничения проверяются при применении.
dry_run=false — одна группа транзакций, один шаг Undo, полный откат при
ошибке, предупреждении или несоответствии значений после Commit. Новое value
не может быть null. Параметры типов изменяют все экземпляры соответствующего типа.

Для существующих типоразмеров открытого семейства использовать
`set_revit_family_type_parameters`: до 20 типоразмеров в одном атомарном пакете,
для каждого значения обязательны `parameter_id`, точное `expected_value` из
`get_revit_family_document` и новое `value`; для Double также
`value_units: "revit_internal"`. Команда восстанавливает выбранный до записи
типоразмер, откатывает весь пакет при предупреждении или несовпадении и не
сохраняет семейство на диск.

## Таймауты и ограничения

Revit API модели вызывается только из обработчика ExternalEvent. HTTP-поток
сигнализирует событие и отправляет WM_NULL главному окну Revit: запросы выполняются
и при работе в другом приложении, без активации окна Revit. HWND читается один раз
при запуске моста в API-контексте. Таймер повторяет сигнал через 250 мс только
при непустой очереди, чтобы не терять запросы при Pending/TimedOut и на границе
возврата обработчика. После опустошения очереди пробуждения прекращаются;
остановка моста отменяет очередь и освобождает событие/таймер. Открытый модальный
диалог или активная команда Revit по-прежнему могут задерживать выполнение.
Общая непотокобезопасная очередь Loader
не используется. Занятый Revit может отвечать health, но не исполнять команды.
Ожидание — 30 секунд. Запрос, ещё не начатый к таймауту, атомарно отменяется.
Если он уже исполняется, ответ сообщает outcome_pending: проверить
get_revit_operation вместо повторной записи. UUID запроса предотвращает
повторное выполнение одинакового тела в пределах хранилища результатов.
Результаты хранятся минимум 15 минут до остановки/перезапуска моста. Перезапуск
меняет session_id; после утраты результата сначала перечитать модель.

Версия 1.1.0 умеет атомарно создавать типоразмеры в открытом редакторе семейства
из существующего базового типа и задавать доступные параметры FamilyManager.
Команда проверяет отсутствие имён, revision, единицы и доступность параметров,
откатывает весь пакет при ошибке или предупреждении и не сохраняет файл.

Версия 1.2.0 добавляет атомарную запись параметров существующих типоразмеров
FamilyManager с dry-run, контролем revision и expected_value, проверкой после
Commit и восстановлением исходного CurrentType.

Версия 1.2.2 отключила автозапуск при загрузке Revit. В текущей версии 1.0.9
запуск дополнительно отделён от просмотра состояния: подключение включается
только действием «Запустить мост» внутри окна.

Версия 1.2.3 подключает PNG из Imagens и смену иконок через Loader по шаблону KPLN.

Версия 1.2.4 заменяет цветные иконки чёрными для светлой темы и двухцветными
светло-серыми с графитовым контуром для тёмной/серой поверхности ленты.

Версия 1.2.5 выполняет запросы через ExternalEvent с фоновым пробуждением WM_NULL.
Мост не требует держать Revit на переднем плане и не переключает фокус. Ручной
запуск, иконки, идентичность документов и точная проверка Double сохранены.

Версия 1.2.1 исправляет преобразование дробных JSON-чисел из Decimal в Double
на .NET Framework: исходное значение восстанавливается через десятичный текст
с invariant culture. Это устраняет ложный конфликт expected_value и округление
нового value для параметров проекта и FamilyManager. Сравнение остаётся точным,
без допуска; действительно устаревшие значения отклоняются.

Ограничения: нет произвольного исполнения C#/Python, создания новой геометрии,
изменения формул, записи в связи, сохранения/синхронизации файлов и проверки
пересечений со связями. Проверка текущего проекта доступна с 1.0.8 через
ElementIntersectsElementFilter; габариты не заменяют точную геометрию.
Навык и хранилище знаний не содержат заранее обученных инженерных решений.

## Чтение модели и пересечения — 1.0.8

Мост предоставляет факты, а не баллы и не критерии найма. Новые операции чтения
не открывают транзакций, не сохраняют модель и не требуют захвата окна Windows.
С версии 1.0.9 всего MCP-инструментов: 26. `get_revit_elements` больше не падает на
`LocationPoint.Rotation` групп, помещений и других неподдерживаемых элементов:
точка возвращается, `rotation_radians=null`, `rotation_status=not_supported`.
Ноль не подставляется вместо отсутствующего угла.

| Инструмент | Данные и границы |
|---|---|
| `get_revit_group_members` | Прямые члены группы с исходным порядком `member_index`, тип, родитель, рабочие наборы, привязанные группы детализации. Вложенные группы обходить отдельно. |
| `get_revit_sheet_contents` | Viewport → вид, масштаб, шаблон; размещённые спецификации и основные надписи. |
| `get_revit_view_elements` | Постраничный список потенциально видимых элементов размещённого вида. |
| `get_revit_view_visibility` | Для указанных элементов: принадлежность выборке вида, индивидуальное/категорийное скрытие, рабочие наборы, фильтры (видимость и включение), показ групп детализации. |
| `get_revit_schedule_data` | Поля и их итоги, фильтры, сортировка/группирование и общие итоги; текст ячеек header/body с пагинацией строк и столбцов. |
| `check_revit_intersections` | Самостоятельная проверка через Revit API для двух явно заданных списков ID категорий текущего проекта. |

`potentially_visible=true` **не доказывает видимость на печати**: Revit может
дополнительно исключить элементы обрезкой вида или перекрыть другими элементами.
`matched_filters` означает совпадение условий фильтра, а не то, что он включён
или скрывает элемент: смотреть `enabled` и `visible`. Настройки рабочего набора
нужно читать вместе с `is_open` и `visible_by_default`. Параметры вида (фаза,
обрезка и т. п.) дополнительно доступны через `get_revit_elements`.

Ячейки спецификации — форматированный текст, не сырые числа и не соответствие
«строка → элемент». Выражения вычисляемых полей и вложенное определение
спецификации не прочитаны; это явно указано в ответе. Для каждой страницы строк
обойти страницы столбцов до `next_column_offset=null`, затем перейти по
`next_offset`. Весь набор собирать при одной `document_id/revision`.

### API-проверка всей модели (мост 1.0.13, контракт 2)

Помещения (`OST_Rooms`) и камеры (`OST_Cameras`) исключаются до чтения геометрии.
Их количество отражается в `excluded_counts`, они не делают результат неполным.
Для поверхностной геометрии `geometry_details` различает объёмные solid,
solid с гранями и нулевым объёмом, Mesh и отдельные Face. Наличие такой записи
не означает коллизию или полное исключение элемента: его объёмная геометрия
по-прежнему участвует в проверке, если поддерживается API.

`check_revit_intersections` использует `ElementIntersectsElementFilter`.
[Autodesk описывает](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/404df79f-2e48-ad4d-2654-a49aa5bf4443.htm)
его как механизм с той же логикой определения пересечений, что и Interference
Report. Это **не управление штатным диалогом и не экспорт его отчёта**:
`method=revit_api_element_intersects_element_filter`, `native_dialog_executed=false`.
Сохраняются ограничения Autodesk: элементы без solid-геометрии и некоторые
автоматически соединённые элементы не обнаруживаются.

Область — геометрия всех экземпляров текущего документа без фильтров по
категории, виду, выделению или рабочему набору. Параметры категорий удалены;
старые HTTP-запросы с ними отклоняются. ViewSpecific/виды и типы не участвуют,
контейнеры групп исключены, но их члены проверяются отдельно. Геометрия читается
в Fine с IncludeNonVisibleObjects=true, без Options.View, включая вложенные
GeometryInstance. Solid с положительным объёмом допускаются к API-фильтру.
По указанию пользователя от 2026-10-06 действует `geometry_policy=test_model_volume_only`:
элементы без объёмного Solid исключаются, даже при наличии bbox, Mesh или поверхностей.
Это упрощение для тестовых моделей, не доказательство отсутствия геометрических дефектов.
Необъёмная часть вместе с Solid сохраняется в `geometry_notes` и не даёт incomplete.
Исключения учитываются в `non_volumetric_elements` и `excluded_counts`.
Ошибки чтения геометрии и неподдержанные API объёмные элементы по-прежнему дают incomplete.

Самопары и зеркальные пары исключены. Ограничение 2000 элементов удалено.
max_pairs: 1–5000 (по умолчанию 1000); time_budget_seconds: 1–60 (по умолчанию 20).
В бюджет входит и обход геометрии; отдельный API-вызов нельзя безопасно прервать.
Лимит времени/пар, неподдержанные элементы, ошибки API, закрытые рабочие наборы
или экземпляры связей дают `complete=false/status=incomplete`. Связанные документы
не проверяются: их экземпляры перечисляются в unprocessed_link_instances.
Пустой набор объёмных элементов даёт `empty_scope`, не успешную проверку. Только
`complete=true/status=no_intersections` даёт сообщение «Пересечения не обнаружены»
**в области и пределах этого API-механизма**. При таймауте читать сохранённую
операцию через `get_revit_operation`, не запускать сразу второй прогон.

Запуск штатного диалога удалён из MCP и диспетчера моста по указанию пользователя.
Новая проверка read-only: не открывает окна, не меняет вид/модель и не сохраняет её.
Факт API-проверки является штатным рабочим сценарием, а не обходным вариантом.
При обновлении нужны новая DLL и перезапуск MCP-клиента для новой схемы инструмента.

### Обновление и интеграционная проверка

После публикации сохранить свою работу и перезапустить нужный Revit, затем
`KPLN → BIM → Codex Мост → Запустить мост`. Остановка/запуск моста в том же

чтобы появился новый список инструментов. Health должен показывать `1.0.8`.

новую оценку модели или подтверждённое отсутствие пересечений.

## Проверка

### Экспорт всех листов в PDF — 1.0.9

`export_revit_sheets_pdf(document_id, expected_revision, dry_run=True)` возвращает
перечень всех листов, печатаемых листов и причин пропусков. После просмотра плана
`dry_run=False` экспортирует все печатаемые листы через штатный `Document.Export`
и `PDFExportOptions` Revit 2023/2024. Revit 2020 явно возвращает
`unsupported_revit_version`: нового механизма печати/драйвера здесь нет.

Выбрано штатное API: текущая «Пакетная выдача» KPLN_Publication использует
приватный обработчик WinForms, PrintManager и PDF-принтер, а для PDFCreator также
настройки реестра. Её готового автономного API нет. Код пакетной выдачи не изменён.

Каждый лист экспортируется в отдельный файл `sheet-<порядок>-<ElementId>.pdf`.
Листы упорядочены по SheetNumber (Ordinal), затем ElementId. Размер бумаги —
`ExportPaperFormat.Default` / Use Sheet Size, то есть размер самого листа и 100%.
Цвет сохраняется; границы обрезки, области видимости и рабочие плоскости скрыты.
Непривязанные обозначения видов не скрываются, чтобы их можно было проверить.
Произвольное имя/путь вывода клиент не задаёт. Каждый запуск создаёт новый каталог
`%LOCALAPPDATA%\KPLN\RevitMcpBridge\exports\<UTC>-<GUID>` без перезаписи прежних PDF.

Ответ и `manifest.json` содержат ID/UniqueId/номер листа, абсолютный путь, размер,
SHA256, document_id, ревизию запроса, настройки, ошибки и пропуски. Проверяются
успех Revit, наличие файла и сигнатура PDF. Листы-заготовки и непечатаемые листы
явно перечисляются; при любой ошибке/пропуске `complete=false`. До 200 листов за
вызов; большее количество отклоняется до экспорта. Транзакции, сохранение модели,
изменения принтера и настроек печати не выполняются.

Экспорт может занять больше таймаута HTTP. Если команда уже выполняется, читать
результат по operation_id через `get_revit_operation`, **не запускать её заново**.
Если очередь отменила ещё не начатую команду, это явно указано в ошибке.

Для визуального контроля скопировать готовые PDF и манифест в папку доказательств
проверки, проверить SHA256 и количество листов/страниц, затем открыть/отрендерить
каждый PDF. Факт экспорта не подтверждает правильность оформления. Проверять
физический формат страницы, рамку, обрезку видов, читаемость, размеры, подписи и
ссылки по конкретному заданию. Оценочные критерии остаются во внешнем слое правил.

После публикации требуется перезапуск Revit и ручное включение моста. Health
должен показывать `1.0.9`. Для появления инструмента в списке MCP переподключить
сервер `revit`. Автотесты используют синтетический API; фактический PDF и его
визуальную проверку подтверждать только после живого прогона в Revit.

```powershell
./scripts/test.ps1 -Python ./.venv/Scripts/python.exe
```

Python: транспорт, схемы, ошибки, реальное MCP initialize/list_tools/call_tool
через stdio. C#: гонки отмены, реальный localhost HTTP со службой Revit-дублем,
вызовы ExternalEvent без Idling, пробуждение фонового окна, пакеты запросов,
повтор сигнала, гонка Pending при возврате события, отсутствие пробуждений
при пустой очереди, отмена при занятости и освобождение события при остановке;
атомарность параметров и откат после Commit на API-дублях; отдельный Lifecycle
