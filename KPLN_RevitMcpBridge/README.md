# KPLN_RevitMcpBridge

Отдельный проект Visual Studio для связи Revit 2020/2023/2024 с Codex.
Загружается **только через KPLN_Loader**: `KPLN_RevitMcpBridge.Module`
реализует `KPLN_Loader.Common.IExternalModule.Execute/Close`.
Мост **выключен после каждого запуска Revit**. Загрузка модуля создаёт только
кнопку: HTTP-порт не открывается и сессия для Codex не публикуется.
Нажатие **KPLN → BIM → Codex Мост** только открывает окно состояния.
Если мост остановлен, доступно действие **«Запустить мост»**; если работает —
**«Остановить мост»**. После действия команда завершается, окно не открывается
повторно. Актуальное состояние видно при следующем нажатии кнопки на ленте.
Закрытие окна не меняет подключение. Повторное открытие после остановки
не запускает мост; состояние не сохраняется между запусками Revit.
Кнопка добавляется на первом Idling после загрузки остальных модулей, чтобы
не конфликтовать с созданием панели BIM в KPLN_BIMTools_Ribbon.

## Иконки кнопок

Схема соответствует `00_KPLN_Templates/KPLN_CSharp_Template`: общий метод
`AddPushButtonDataInPanel` принимает базовое имя иконки (`mcpBridge`) и получает
изображения 16/32 через `KPLN_Loader.Application.GetBtnImage_ByTheme`.
В `Imagens` хранятся четыре PNG: `mcpBridge16.png`, `mcpBridge32.png` для светлой
темы и `mcpBridge16_dark.png`, `mcpBridge32_dark.png` для тёмной. Все четыре файла
подключены в `.csproj` как **Resource** и встраиваются в DLL; копировать PNG
рядом с DLL не нужно. Loader читает их через WPF pack URI.

Цветовая схема: стандартная светлая тема — чёрный знак; вариант `_dark` —
нейтральный светло-серый знак с тонким графитовым контуром. Светлая часть видна
на тёмном фоне, контур отделяет знак от светлого серого. Фон PNG прозрачный.
Loader выбирает ресурс по `UIThemeManager.CurrentTheme`, а не по цвету фона
вида/модели; вариант `_dark` рассчитан также на серые поверхности интерфейса.

Сборка выполняется в Visual Studio либо `scripts/build.ps1`, который находит
MSBuild.exe из Visual Studio / Build Tools (можно задать `-MSBuildPath`).
`dotnet msbuild` для основного проекта запрещён: в этом классическом проекте
он пропускает упаковку WPF Resource и создаёт DLL без иконок.

В Revit 2024 кнопка регистрируется в `KPLNButtonsForImageReverse`: при смене
темы Loader обновляет обе иконки. В конфигурациях Revit 2020/2023 эта регистрация
исключена директивой компиляции, как в шаблоне. Для новой кнопки нужно добавить
аналогичный комплект `{имя}16.png`, `{имя}32.png`, `{имя}16_dark.png`,
`{имя}32_dark.png` как Resource и передать только базовое имя в общий метод.

## Архитектура

```text
Codex → MCP stdio (Python FastMCP) → HTTP 127.0.0.1
  → KPLN_RevitMcpBridge.dll → потокобезопасная очередь → ExternalEvent → Revit API

KPLN_RevitRules ← тонкий навык Codex: правила, проектные решения, записи анализа
```

Как в KPLN_NavisMcpBridge / KPLN_NavisClashRules, транспорт и Revit API
отделены от инженерных решений. C# извлекает данные и выполняет транзакции,
Python предоставляет MCP-инструменты. Правила не компилируются в DLL и
не встроены в MCP-сервер. Логика нормализации здесь проста: геометрия в мм,
Double-параметры сохраняют внутренние единицы Revit с указанием типа величины.

## Сборка и KPLN_Loader

Открыть `KPLN_RevitMcpBridge.sln`. Конфигурации `Debug2020/2023/2024` и
`Revit2020/2023/2024`, x64, .NET Framework 4.8, C# 7.3.
Нужны установленные Revit API и DLL вашего Loader по пути
`X:\BIM\5_Scripts\SetupFiles\Revit\1.Common\KPLN\<год>\KPLN_Loader\KPLN_Loader.dll`.
Пути переопределяются свойствами MSBuild `RevitApiRoot` и `LoaderRoot`.

Конфигурации проекта объявлены явными парами `Debug2023|x64` и т. п.;
платформы Any CPU нет. F5 запускает `Revit.exe` выбранного года как внешнюю
программу. После изменения проекта согласиться на Reload в Visual Studio
или заново открыть solution, затем выбрать нужную конфигурацию и x64.

При Debug-сборке DLL и PDB сначала создаются в `bin\Debug\<год>`, затем
копируются в `bin\<год>`, откуда их забирает зарегистрированный Loader.
Это заменяет сборку этого года в папке публикации на отладочную. Таким образом
Loader загружает свежую DLL с символами, а не старую release-сборку. Папку
можно переопределить через `LoaderModuleRoot`, копирование отключить через
`/p:CopyDebugToLoader=false`. Повторная Revit-сборка возвращает release DLL.
Если DLL уже загружена в открытый Revit, для проверки новой сборки перезапустить
этот экземпляр или запускать новый через F5; Attach к старому процессу DLL не обновляет.

```powershell
./scripts/build.ps1
```

Release-сборки лежат в `bin\2020`, `bin\2023`, `bin\2024`.
В менеджере БД KPLN_Loader создать запись:

| Поле | Значение |
|---|---|
| Name | KPLN_RevitMcpBridge |
| Path | полный путь к `KPLN_RevitMcpBridge\bin` |
| IsEnabled | True |
| IsLibraryModule | False |
| IsDebugMode | по принятому порядку тестовой публикации |

Назначить модуль нужным подразделениям в `ModulesMatrix`. Loader фильтрует
модули по этой матрице — одной записи Modules недостаточно. Для обычного
модуля `CopyModule` выбирает `Path\<год>`, даже у пользователя в debug-режиме;
папка `Debug\<год>` используется Loader только для библиотек. Поэтому запись
указывает на release `bin`, либо на специально подготовленную папку публикации
с подпапками годов. DLL Loader/Revit API рядом с модулем не копируются.

При установке в ExtraNet скопировать DLL нужного года в
`<папка KPLN_Loader>\Modules\KPLN_RevitMcpBridge\`.
Самостоятельный `.addin` для этого проекта не нужен. Изменять код Loader не нужно.
Перезапустить Revit после регистрации/обновления модуля; уже открытый процесс
новую DLL сам не подхватит. Регистрация в общей БД не производится скриптами
этого проекта: область назначения в ModulesMatrix выбирается в менеджере БД.

## Подключение Codex

Создать отдельное Python-окружение (3.11+ для установщика), затем:

```powershell
python -m venv .venv
./.venv/Scripts/python.exe -m pip install -r server/requirements.txt
./.venv/Scripts/python.exe scripts/install_codex.py --python .venv/Scripts/python.exe
../KPLN_RevitRules/scripts/install-skill.ps1
```

Установщик добавляет `[mcp_servers.revit]` в конфигурацию Codex с резервной
копией, сохраняет остальные серверы и не меняет пользовательскую политику
подтверждений. Если revit уже настроен иначе, отказывается его перезаписывать.
Перезапустить MCP/открыть новую задачу, чтобы загрузились инструменты и навык.
Формат подключения: [официальная документация Codex MCP](https://developers.openai.com/codex/mcp).

После выбора «Запустить мост» в окне состояния мост выбирает свободный порт 18765–18784 и пишет описание сессии в
`%LOCALAPPDATA%\KPLN\RevitMcpBridge\sessions\<session_id>.json`.
Там хранится локальный ключ; его не надо копировать в репозиторий или переписку.
MCP автоматически находит сессии. При нескольких открытых Revit обязательно
указать session_id. Все HTTP-запросы требуют токен; Origin и перенаправления
не поддерживаются. Если HttpListener сообщает Access denied, администратор
должен разрешить выбранный localhost URL через Windows HTTP URL ACL; ошибка
видна по кнопке моста. Правила брандмауэра для внешнего доступа не нужны.

## Инструменты

| Область | Инструменты |
|---|---|
| Сессии и диагностика | list_revit_sessions, get_revit_bridge_health, get_revit_operation |
| Документ | get_revit_documents, get_revit_context |
| Элементы | get_revit_selection, get_revit_categories, find_revit_elements, get_revit_elements |
| Виды и связи | get_revit_views, get_revit_links |
| Семейства | get_revit_families, get_revit_family_types, get_revit_family_document |
| Действия | select_revit_elements, set_revit_parameters, create_revit_family_types, set_revit_family_type_parameters |

Чтение элементов работает в активном документе. `document_id` проверяется
при каждом запросе, чтобы переключение файла в Revit не перенаправило команду.
Страницы возвращают `next_offset`; сравнивать их следует при одной `revision`.
`get_revit_context` возвращает документ и revision внутри result.document.
Другие команды возвращают document_id и revision на верхнем уровне ответа.

Для записи передать `document_id`, `expected_revision` и до 200 updates:
`element_unique_id`, `parameter_id`, `expected_value`, `value`; для Double также
`value_units: "revit_internal"`. dry_run по умолчанию true. План проверяет
параметры без транзакции; реальные ограничения проверяются при применении.
dry_run=false — одна группа транзакций, один шаг Undo, полный откат при
ошибке, предупреждении или несоответствии значений после Commit. Новое value
не может быть null. Параметры типов изменяют все экземпляры соответствующего типа.

Для существующих типоразмеров открытого семейства использовать
`set_revit_family_type_parameters`: до 20 типоразмеров в одном атомарном пакете,
для каждого значения обязательны `parameter_id`, точное `expected_value` из
`get_revit_family_document` и новое `value`; для Double также
`value_units: "revit_internal"`. Команда восстанавливает выбранный до записи
типоразмер, откатывает весь пакет при предупреждении или несовпадении и не
сохраняет семейство на диск.

## Таймауты и ограничения

Revit API модели вызывается только из обработчика ExternalEvent. HTTP-поток
сигнализирует событие и отправляет WM_NULL главному окну Revit: запросы выполняются
и при работе в другом приложении, без активации окна Revit. HWND читается один раз
при запуске моста в API-контексте. Таймер повторяет сигнал через 250 мс только
при непустой очереди, чтобы не терять запросы при Pending/TimedOut и на границе
возврата обработчика. После опустошения очереди пробуждения прекращаются;
остановка моста отменяет очередь и освобождает событие/таймер. Открытый модальный
диалог или активная команда Revit по-прежнему могут задерживать выполнение.
Общая непотокобезопасная очередь Loader
не используется. Занятый Revit может отвечать health, но не исполнять команды.
Ожидание — 30 секунд. Запрос, ещё не начатый к таймауту, атомарно отменяется.
Если он уже исполняется, ответ сообщает outcome_pending: проверить
get_revit_operation вместо повторной записи. UUID запроса предотвращает
повторное выполнение одинакового тела в пределах хранилища результатов.
Результаты хранятся минимум 15 минут до остановки/перезапуска моста. Перезапуск
меняет session_id; после утраты результата сначала перечитать модель.

Версия 1.1.0 умеет атомарно создавать типоразмеры в открытом редакторе семейства
из существующего базового типа и задавать доступные параметры FamilyManager.
Команда проверяет отсутствие имён, revision, единицы и доступность параметров,
откатывает весь пакет при ошибке или предупреждении и не сохраняет файл.

Версия 1.2.0 добавляет атомарную запись параметров существующих типоразмеров
FamilyManager с dry-run, контролем revision и expected_value, проверкой после
Commit и восстановлением исходного CurrentType.

Версия 1.2.2 отключила автозапуск при загрузке Revit. В текущей версии 1.0.7
запуск дополнительно отделён от просмотра состояния: подключение включается
только действием «Запустить мост» внутри окна.

Версия 1.2.3 подключает PNG из Imagens и смену иконок через Loader по шаблону KPLN.

Версия 1.2.4 заменяет цветные иконки чёрными для светлой темы и двухцветными
светло-серыми с графитовым контуром для тёмной/серой поверхности ленты.

Версия 1.2.5 выполняет запросы через ExternalEvent с фоновым пробуждением WM_NULL.
Мост не требует держать Revit на переднем плане и не переключает фокус. Ручной
запуск, иконки, идентичность документов и точная проверка Double сохранены.

Версия 1.2.1 исправляет преобразование дробных JSON-чисел из Decimal в Double
на .NET Framework: исходное значение восстанавливается через десятичный текст
с invariant culture. Это устраняет ложный конфликт expected_value и округление
нового value для параметров проекта и FamilyManager. Сравнение остаётся точным,
без допуска; действительно устаревшие значения отклоняются.

Ограничения: нет произвольного исполнения C#/Python, создания новой геометрии,
изменения формул, записи в связи, сохранения/синхронизации файлов и точных
проверок коллизий. Габариты не заменяют точную геометрию.
Навык и хранилище знаний не содержат заранее обученных инженерных решений.

## Проверка

```powershell
./scripts/test.ps1 -Python ./.venv/Scripts/python.exe
```

Python: транспорт, схемы, ошибки, реальное MCP initialize/list_tools/call_tool
через stdio. C#: гонки отмены, реальный localhost HTTP со службой Revit-дублем,
вызовы ExternalEvent без Idling, пробуждение фонового окна, пакеты запросов,
повтор сигнала, гонка Pending при возврате события, отсутствие пробуждений
при пустой очереди, отмена при занятости и освобождение события при остановке;
атомарность параметров и откат после Commit на API-дублях; отдельный Lifecycle
проверяет выключенное состояние при загрузке, просмотр без запуска, явный
запуск/остановку, повторный просмотр после остановки, ошибку запуска и
повторную загрузку модуля. Сборки используют
реальные API Revit 2020/2023/2024. Эти проверки не заменяют пробу в живой модели.

Приёмка в Revit: загрузить модуль Loader → проверить кнопку в BIM и отсутствие
активной сессии → открыть и закрыть окно (сессии всё ещё нет) → открыть окно и
выбрать «Запустить мост» (окно закрывается) → list_revit_sessions → get_revit_context → выделить один элемент → прочитать
параметр → dry_run на тестовой копии → применить → перечитать → проверить Undo.
Дополнительно проверить переключение документа, занятый Revit, второй экземпляр
Revit и параметр, который Revit запрещает менять. Остановить мост через окно
состояния и проверить исчезновение сессии; повторное открытие окна не создаёт
новую сессию. Для нового подключения явно выбрать «Запустить мост».
После нового запуска Revit мост должен снова оставаться выключенным.
Для проверки фонового режима переключиться в Codex после включения моста и
закрытия окна состояния. Выполнить несколько get_revit_context подряд, затем
dry-run/запись/чтение на тестовой копии, не активируя Revit между запросами.
