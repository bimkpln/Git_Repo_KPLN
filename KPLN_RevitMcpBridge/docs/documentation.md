# Оформление документации, мост 1.1.0

Внешний набор решений: KPLN_OVModelDocumentationRules. В DLL находятся операции
Revit и проверки API; конкретные типы, этажи, координаты и объекты оформления
берутся из модели-образца. Все длины новых команд — мм, векторы — безразмерные.

## Чтение

- get_revit_documentation_catalog: title_blocks (семейства 020_), tag_types,
  dimension_types, view_types, view_templates. Постранично.
- get_revit_sheet_layout: координаты листа, центры/границы/повороты окон,
  типы и шаблоны, точки вставки спецификаций. Заголовки с 2023.
- get_revit_view_annotations: существующие марки, типы, цели, положения;
  размеры, линии и stable_reference. Постранично.
- get_revit_dimension_references: кандидаты привязок элемента, включая
  datum, family references, грани и рёбра. Геометрия связей не обходится.
- get_revit_project_levels: отметки и building_story/structural, одинаковые
  отметки, планы/шаблоны/листы. Выбор проектного этажа остаётся решением агента.

## Создание

Каждая команда принимает document_id, expected_revision, items (1–100),
dry_run (по умолчанию true), session_id. Точные поля доступны в MCP schema.

| Команда | Содержимое items |
|---|---|
| create_revit_sheets | title_block_type_unique_id, number, name |
| place_revit_views | sheet_unique_id, view_unique_id, point_mm либо reference_viewport_unique_id |
| create_revit_tags | view_unique_id, tag_type_unique_id, element_unique_id, head_mm, kind, leader, orientation, optional link_instance_unique_id |
| tag_revit_linked_rooms | view_unique_id, link_instance_unique_id, tag_type_unique_id, optional linked_level_unique_id/orientation |
| create_revit_dimensions | view_unique_id, dimension_type_unique_id, start_mm, end_mm, references |
| create_revit_plan_views | view_type_unique_id, level_unique_id, name, optional template_unique_id/scale/crop_min_mm/crop_max_mm |
| create_revit_sections | view_type_unique_id, name, origin_mm, up, direction, min_mm, max_mm, optional template_unique_id/scale |

point_mm для вида — центр окна в системе листа (Z=0), для спецификации —
точка вставки. Образец окна в том же документе даёт центр/тип/поворот/заголовок.
head_mm и линии размеров — внутренние координаты документа. Для связанной
цели element_unique_id относится к связи, head_mm — к активному документу.
kind: independent, room, space; связанные пространства не поддерживаются.
Размеры: линейные и цепочки; ссылки извлекать из API, не выдумывать.
Разрез: базис (up×direction, up, direction), min/max — в этом локальном базисе.

dry_run выполняет настоящее создание и Commit внутри TransactionGroup с
последующим откатом. ID из такой пробы не использовать; повторно получить
revision. Любая ошибка/предупреждение откатывает пакет. Реальная запись
атомарна; RVT не сохраняется. После таймаута читать get_revit_operation,
создание не повторять при неизвестном результате. На массовых операциях
использовать небольшие пакеты и проверять читаемость листов визуально.

Изменения DLL вступают в силу после полного перезапуска Revit. MCP Python
также нужно перезапустить для обновления списка инструментов.

## Пакетная маркировка помещений связи (1.1.5)

Алгоритм перенесён из pyKPLN_MEP «Помещения & Пространства / Маркировка»:
точка Room.Location преобразуется через GetTransform конкретного экземпляра
связи, NewRoomTag получает LinkElementId(экземпляр связи, помещение).
В запросе items содержит сочетания плана, экземпляра связи и RoomTagType;
все UniqueId, кроме linked_level_unique_id, относятся к текущему документу.
Тип марки можно прочитать через get_revit_documentation_catalog(tag_types).

- Только планы этажей/потолков, не шаблоны. Марки ставятся без выносок,
  orientation: Horizontal (по умолчанию) или Vertical.
- Уровень связи определяется по ProjectElevation с учётом преобразования
  связи и допуском 10 мм к уровню плана. Если совпадений нет или больше одного,
  запрос отклоняется. linked_level_unique_id задаёт явное соответствие,
  например, для разных отметок АР и ОВ; при этом отметки не сравниваются.
- Стадия определяется из GetPhaseMap типа связи для VIEW_PHASE плана.
  Отбираются помещения этого уровня и ROOM_PHASE_ID.
- Уже существующая неосиротевшая марка той же цели на том же виде
  блокирует дубль независимо от типа/видимости марки. Разные экземпляры
  одной связи различаются. Осиротевшие марки не удаляются.
- Неразмещённые помещения и помещения с нулевой площадью пропускаются.
  Проверяется точка размещения, а не пересечение контура помещения с видом.
  При активной подрезке точка должна входить в прямоугольник в его локальных
  координатах. Z подрезки не используется: этаж задан соответствием уровней.
  Непрямоугольная и разделённая подрезка отклоняются; для них доступно
  create_revit_tags с явными помещениями и координатами.
- Поддерживаются перенос, поворот в плане и зеркальность связи с осью Z вверх.
  Выгруженная/явно скрытая связь, скрытая категория марок, неверный тип,
  наклон связи и отсутствие сопоставления стадий дают явную ошибку.
- Отбор по уровню, стадии и подрезке не воспроизводит все настройки видимости
  Revit: фильтры, варианты, режим «По связанному виду», пользовательские
  настройки стадий/категорий связи и временное скрытие. Требуется визуальная
  проверка результата. Раскладка марок и устранение наложений не выполняются.

Весь запрос ограничен 1000 новыми марками. При превышении или ошибке Revit
откатывается весь пакет, в том числе ранее обработанные планы. dry_run=true
выполняет создание/Commit и откат; после него нужна свежая revision.
RVT не сохраняется. В ответе для каждой строки: фактически выбранные уровень
и стадия, matched_room_count, created_count, skipped по причинам,
tags с UniqueId помещений, номерами и созданными марками. ID пробных марок
недействительны; исходные UniqueId помещений и планов остаются действительными.
