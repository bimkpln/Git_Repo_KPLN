# Проверки арматуры через Codex Мост (1.1.14)

Две проверки относятся к **частным критериям КР**:
- CheckIfcRebarMarks — марки IFC-арматуры;
- CheckRebarConcreteClass — класс бетона погонной арматуры.

## Зависимости и установка

Нужны загруженная KPLN_ModelChecker_User с двумя новыми командами и
KPLN_RevitMcpBridge версии 1.1.14+, а также соответствующий Server/revit_mcp_server.py.
Исходники проверок находятся в проекте KPLN_ModelChecker_User (ветка
mtarchokov_ModelChecker_User); адаптер — в проекте KPLN_RevitMcpBridge.
Мост не загружает произвольные DLL и не обращается к старым pyRevit-кнопкам TEST.

Установить собранную DLL моста для своей версии Revit в расположение модуля,
используемое KPLN_Loader, при закрытом Revit. В MCP-подключении использовать
обновлённый Python-сервер из этого проекта с зависимостями Server/requirements.txt.
Перезапустить Revit для замены загруженной DLL и MCP-подключение для обновления
каталога инструментов. Reload pyRevit не обновляет native DLL этого моста.
Включить KPLN → BIM → Codex Мост. Мост запускается только пользователем.

## Порядок работы

1. list_revit_sessions → выбрать сессию.
2. get_revit_context → проверить активную модель, получить document_id.
3. get_revit_kr_check_catalog → проверить available и получить library_module_id.
4. Перед каждым запуском снова get_revit_context → свежая expected_revision.
5. run_revit_kr_check с document_id, session_id, expected_revision,
   library_module_id и одним из двух check_id.
6. Если outcome_pending, продолжить get_revit_operation с возвращённым
   operation_id, не отправлять повторный запуск. При обрыве HTTP также сначала
   запросить состояние операции по ID из ошибки клиента.
7. Результат содержит исходные счётчики, status, notes, result_id и section_counts.
   Прочитать через get_revit_kr_check_result ВСЕ страницы каждого раздела
   issues, skipped_elements, run_warnings до has_more=false.
8. completed означает завершение алгоритма, а не отсутствие ошибок.
   Подтверждённые ошибки отделять от геометрических неопределённостей и ограничений.

## Поведение и ограничения

- Вызываются существующие RunJson из уже загруженной KPLN_ModelChecker_User.
  Алгоритмы выбора стержней, основы, исключений и сравнения не меняются.
- Доступ через тот же KRCheckAccess.IsAllowed, что у кнопок: только КР/BIM.
  При отсутствии/изменении этого контракта мост отказывает, а не обходит доступ.
- Выполнение на потоке Revit API, без транзакций, изменения параметров и сохранения
  модели. Итоговое окно отчёта не открывается. Длительный расчёт занимает Revit.
- Каталог показывает причины недоступности; сборка сверяется по ModuleVersionId.
- Результаты привязаны к документу и ревизии запуска. При изменении модели
  чтение сохраняет снимок, но возвращает is_stale=true.
- Кэш живёт в сессии моста: до 30 минут, максимум 4 отчёта и суммарно 64 млн
  символов исходного JSON. Старые отчёты вытесняются; остановка моста очищает кэш.
  Один слишком большой/некорректный отчёт даёт явную ошибку, не пустой успех.
- Связи и закрытое содержимое не добавляются в область проверки.
- Unit/transport-тесты и сборка не заменяют контрольный запуск в настоящем Revit.
