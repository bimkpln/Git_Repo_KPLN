# Положение заголовка на листе — 1.1.12

`update_revit_viewport_labels` / HTTP `update_viewport_labels` изменяет
`Viewport.LabelOffset` и необязательно `LabelLineLength` существующих окон.
Центр и поворот плана сохраняются; масштаб, тип окна и содержание вида не меняются.
Поддержаны Revit 2023/2024/2026; Revit 2020 возвращает `unsupported_version`.

Сначала читать `get_revit_sheet_layout`, затем передавать `document_id`,
`expected_revision`, `items` и `dry_run` (по умолчанию true). Запись:

- `sheet_unique_id`, `viewport_unique_id` — реальные идентификаторы;
- `expected_label_offset_mm` — прочитанное `label_offset_mm`;
- `label_offset_mm` — новое смещение; обе тройки в мм бумаги, Z=0;
- `expected_label_line_length_mm` и `label_line_length_mm` — необязательная
  пара значений длины в мм. Отрицательная длина допустима в Revit API.

Смещение — вектор API от нижнего левого угла окна при Rotation=None до начала
линии заголовка, а не абсолютная точка/центр текста. Для повёрнутых окон
не применять формулы неповёрнутого окна; проверять `label_bounds` и PDF.
Начало линии и край текста могут различаться в зависимости от семейства.

Проверяются принадлежность листу, закрепление, группы, повтор окна в пакете,
конечные координаты, ожидаемые значения с допуском 0.1 мм. После Regenerate
проверяется результат и неизменность положения плана. После Commit действует
общая проверка всех габаритов затронутых листов; ошибки откатывают группу.
Эта проверка использует границы бумаги. Измеренное поле рамки и штамп проверять
дополнительно `check_revit_sheet_layout`; итог — обязательно по PDF.

Если заголовок отключён типом окна, команда настраивает его положение,
но не включает видимость. После включения подходящего типа проверить лист.
`dry_run` выполняет Commit с откатом: получить свежую revision перед записью.
RVT не сохраняется и не синхронизируется.

Для загрузки новой DLL требуется полный перезапуск Revit после сохранения
пользователем изменений. MCP-процесс также должен перечитать Python-сервер.
