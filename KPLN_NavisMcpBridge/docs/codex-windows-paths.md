# Codex и Windows-пути

Эта памятка фиксирует рабочие договорённости для Codex/Windows вокруг
`KPLN_NavisMcpBridge`. Она не расширяет полномочия MCP-сервера: сервер остаётся
слоем команд к Navisworks и не читает произвольные файлы с диска.

## Канонические пути

- Основной путь проекта: `X:\BIM\5_Scripts\Git_Repo_KPLN\KPLN_NavisMcpBridge`
- UNC-вариант той же папки: `\\fs01\bim_data\BIM\5_Scripts\Git_Repo_KPLN\KPLN_NavisMcpBridge`

В разных процессах Windows сетевой диск `X:` может быть не смонтирован. Если
команда не видит `X:`, используйте UNC-вариант.

## PowerShell

- Для путей используйте `-LiteralPath`, особенно если в имени есть `_`, скобки,
  пробелы или кириллица.
- Оборачивайте путь в одинарные кавычки:
  `Get-Content -LiteralPath 'X:\BIM\5_Scripts\Git_Repo_KPLN\KPLN_NavisMcpBridge\README.md' -Encoding UTF8`
- В Markdown подчёркивания не нужно экранировать обратным слэшем внутри обычного
  inline-code: пишите `5_Scripts`, а не `5\_Scripts`.

## Кодировка

- Файлы проекта хранить в UTF-8.
- В Windows PowerShell 5.1 при чтении текстовых файлов явно указывать
  `-Encoding UTF8`, иначе кириллица может отобразиться как mojibake.
- Для Python/CLI-вывода с кириллицей лучше сохранять JSON/отчёт в UTF-8 файл и
  читать его с явной кодировкой, чем полагаться на кодовую страницу консоли.

## Граница ответственности

- C# add-in: только данные Navisworks через localhost HTTP.
- Python MCP-server: команды чтения/записи Navisworks и нормализованные метрики.
- Skill: инженерные правила, проектные пороги, обучение и решения по статусам.

Не добавляйте в MCP-сервер универсальные команды чтения файлов, обхода дисков
или эвристики по старым путям проектов. Если Codex нужны файлы репозитория, это
решается разрешениями рабочего окружения, а не Navisworks-мостом.
