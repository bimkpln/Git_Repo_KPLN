# KPLN_Tools_Lib

Общие команды для инженерных выпадающих списков `KPLN_Tools_EOM`, `KPLN_Tools_OVVK` и `KPLN_Tools_SS`.
Первая команда — «Создать пространства», перенесённая из pyKPLN:
`pyKPLN_MEP/KPLN.extension/pyKPLN_MEP.tab/Помещения & Пространства.panel/Создание.pushbutton/script.py`.
Иконка сохранена из этой же команды.

## Подключение

Проекты-потребители вызывают `ToolsRibbon.AddCreateSpacesButton(PulldownButton)`
и `ToolsRibbon.AddTagSpacesButton(PulldownButton)`.
Кнопка ссылается на публичный `CreateSpacesExtCmd` из общей DLL. Библиотека не создаёт отдельную панель
и не реализует `IExternalModule`. Модальное окно использует `KPLN_Library_Forms/UI/LibStyles.xaml`;
после его закрытия команда вызывает сервис в исходном контексте Revit API.

Поддерживаемые конфигурации: Debug2020, Debug2023, Debug2024 и соответствующие Revit2020/2023/2024.
Зависимости подключены как `Reference` + `HintPath` + `Private=False`.
В решениях трёх модулей библиотека присутствует, но автоматически не собирается: `Build.0` включён
только для целевого проекта. Зависимости собираются отдельно при необходимости. Собственные выходные каталоги библиотеки:
`KPLN_Tools_Lib/bin/Debug/<год>` и `KPLN_Tools_Lib/bin/<год>`.

Цель `CopyToolsLibraryToModule` каждого потребителя копирует разрешённую при сборке `KPLN_Tools_Lib.dll`
в его выходной каталог. При распространении нужно передавать весь комплект модуля, включая эту DLL.
Отдельная запись библиотеки в базе загрузчика не требуется; `KPLN_Library_Forms` и
`KPLN_Library_ConfigWorker` остаются общими зависимостями загрузчика.
Во всех трёх модулях должна распространяться одна версия общей библиотеки.

В ЭОМ создание выпадающего списка доступно для всех поддерживаемых лет; прежние команды проекта
«Сетунь» сохраняют существующее ограничение на Revit 2020.

## Поведение

- Пользователь выбирает загруженные экземпляры связей и стадию пространств. По умолчанию выбраны
  все связи и стадия активного вида; при отсутствии стадии вида используется последняя стадия проекта.
- Помещения берутся на стадии, сопоставленной выбранной стадии в настройках каждой связи.
- Координаты переводятся через `RevitLinkInstance.GetTransform()`. Для уровней используется
  `ProjectElevation`, с учётом вертикального смещения связи и допуском 1 мм.
- Если одной отметке соответствуют несколько уровней, выбирается единственный уровень с именем
  исходного. Если такого нет, помещение пропускается с объяснением.
- Переносятся положение, нижнее смещение и высота помещения. Имя, номер, марки и разделители
  пространств не создаются — их не переносил исходный скрипт.
- Неразмещённые помещения, помещения с нулевой площадью и некорректной высотой пропускаются.
  Наклонённые связи не поддерживаются; поворот вокруг вертикали и отражение в плане допустимы.
- Существующее пространство в той же точке на том же уровне/стадии либо пространство, содержащее
  контрольную точку помещения, пропускается. Повторный запуск после переноса/изменения границ
  пространств требует проверки пользователем.
- Каждое пространство создаётся отдельной транзакцией; ошибка одного помещения не отменяет остальные.
  Успешные изменения объединяются в один шаг отмены. При ошибке регенерации откатывается вся группа.
- Предупреждения Revit сохраняются в отчёте KPLN. Ошибки транзакции приводят к её откату.
  Границы пространств зависят от геометрии проекта и настройки связи «Граница помещений»;
  команда не меняет эту настройку автоматически.

## Проверка в Revit

Сборка не проверяет работу геометрии и транзакций в открытом Revit. Для проверки на копии модели:

1. Убедиться в наличии кнопки во всех трёх списках, в том числе ЭОМ 2023/2024.
2. Проверить отмену, пустой выбор, выбор нескольких экземпляров одной связи, отсутствие загруженных связей.
3. Создать пространства для связи с поворотом и смещением по XYZ; проверить уровни и высоту,
   включая помещение с ненулевым нижним смещением и верхним ограничением на другом этаже.
4. Проверить отсутствующий/неоднозначный уровень, неразмещённое/незамкнутое помещение и предупреждение
   о незамкнутом пространстве. Ошибки должны попасть в отчёт, остальные помещения — обработаться.
5. Повторить запуск: существующие пространства должны быть пропущены. Проверить разные стадии
   и заданное в Revit соответствие стадий связи.
6. Выполнить одну отмену: все пространства последнего запуска должны удалиться вместе.

API: [NewSpace(Level, Phase, UV)](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/ce49bd88-7d6b-b3ca-bd4c-497233718ffb.htm),
[RevitLinkType.GetPhaseMap](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/4d322c11-c2b3-a096-4f10-3b23c9112308.htm).
Доступность использованных API также проверяется сборкой с установленными API 2020/2023/2024.

## Маркировка помещений / пространств

Команда `TagSpacesExtCmd` и иконка перенесены из
`pyKPLN_MEP/KPLN.extension/pyKPLN_MEP.tab/Помещения & Пространства.panel/Маркировка.pushbutton`.
Кнопка «Маркировать помещения / пространства» добавлена после «Создать пространства» во всех трёх списках.

1. Выделить в диспетчере проекта планы этажей / потолков через Ctrl или Shift.
2. Выбрать помещения либо пространства и загруженный тип марки этой категории.
3. Для помещений выбрать текущую модель или один загруженный экземпляр связи. Пространства берутся
   только из текущей модели. Наличие связей для маркировки локальных элементов не требуется.
4. Нажать «Маркировать». Итоговый отчёт показывает созданные, уже маркированные и пропущенные элементы / виды.

Окно `TagSpaces` использует MVVM и общую библиотеку стилей. Сервис вызывается после закрытия модального окна.
Типы марок фильтруются по категории; выбор двух категорий одновременно невозможен. Отмена окна не меняет модель.
Исходный скрипт перебирал все помещения на каждом плане; новая команда ограничивает их уровнем и стадией вида.
Для связи учитываются её преобразование координат (поворот, отражение и смещение), соответствие стадий
и отметка уровня в текущем проекте с допуском 1 мм. Наклонённые связи не поддерживаются.

Для локальных элементов используется коллектор вида. Для связанных помещений — отбор по уровню / стадии,
видимости экземпляра связи и попаданию точки размещения в обрезку. Настройки связи «По связанному виду»,
её пользовательские фильтры и варианты конструкции отдельно не воспроизводятся; такие планы требуют
контрольной проверки. Если точка размещения помещения вне обрезки, марка не создаётся даже при частично
видимом помещении. Разделённая область обрезки пропускается с объяснением в отчёте.

Марка ставится в точке размещения элемента. Неразмещённые элементы и элементы с нулевой площадью пропускаются.
Повторный запуск не создаёт дубликаты; проверка учитывает экземпляр связи, скрытые марки,
основной и зависимые виды. Тип и положение существующих марок не изменяются.
Создание каждой марки выполняется отдельной транзакцией. Ошибка одной марки не отменяет остальные;
все успешные изменения объединены в один шаг отмены. Ошибка регенерации откатывает всю группу.

Проверка в Revit на копии модели:

- Выбор одного / нескольких планов, смешанный выбор, пустой выбор, шаблон вида, отмена окна.
- Обе категории и фильтрация типов; отсутствие подходящих типов; локальные помещения без связей.
- Несколько этажей / стадий; связь со смещением по XYZ, поворотом и отражением; несколько экземпляров одной связи.
- Повторный запуск; скрытые марки; основной и зависимые планы; другая связь с теми же ID помещений.
- Прямоугольная и многоугольная обрезка; незамкнутые помещения; скрытая связь / категория марок;
  разделённая обрезка и ошибки отдельных марок.
- Одна отмена удаляет все марки последнего запуска.

API: [NewRoomTag](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/9847aafe-42f9-fe8e-5229-c491add7ec46.htm),
[RoomTag.TaggedRoomId](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/05449236-668c-3eff-9bf6-33b71b561185.htm),
[GetCropShape](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/36a98b08-72be-4b0a-99f6-4a765b85b15d.htm).

### Общие настройки маркировки

Настройки читаются и сохраняются через `KPLN_Library_ConfigWorker.ConfigService` с `ConfigType.Shared`
и именем `KPLN_Tools_Lib_TagSpaces`. Путь определяет библиотека конфигураций по хранилищу модели:
папка `KPLN_Config` или каталог проекта на Revit Server. Это один общий конфиг для пользователей проекта,
доступный из кнопок всех трёх разделов.

Сохраняются категория, основные типы марок помещений и пространств отдельно, выбранный источник помещений,
две галки учёта оборудования и два дополнительных типа марки пространства. Типы записываются по имени
семейства и типоразмера; ссылку на экземпляр связи восстанавливаем по UniqueId, затем по точному имени.
Объекты Revit и выбранные планы не сериализуются. Если сохранённый тип/связь отсутствует, пользователь должен
выбрать замену, когда соответствующая настройка используется. Неактивные настройки сохраняются и при
переключении категории, и при снятии галки.

Сохранение выполняется по кнопке «Маркировать»; отмена окна не изменяет конфиг. В автономной/отсоединённой
модели или при ошибке доступа команда может применить текущие настройки, но сообщает, что общий конфиг
не сохранён. На Local/Memory автоматически не переключается.

### Марки пространств с радиаторами и решётками

Дополнительный блок виден только для категории «Пространства». Обе галки изначально сняты.
Под каждой галкой свой список **типов марок пространств**: он включается только вместе с галкой.
Автоматического выбора специального типа нет; запуск блокируется, пока тип не выбран. Для пространства
с соответствующим прибором используется специальный тип, для остальных — основной тип марки.
Существующие марки, как и прежде, не заменяются.

Правила распознавания вынесены в `Services/TagSpacesEquipmentRules.cs`, словарь `FamilyPrefixes`:

| Назначение | Категория | Начало имени семейства |
| --- | --- | --- |
| Радиаторы | `OST_MechanicalEquipment` — Оборудование | `554_`, `556_`, `557_` |
| Решётки | `OST_DuctTerminal` — Воздухораспределители | `440_`, `443_`, `444_` |

Оборудование берётся **только из текущей модели и с обрабатываемого вида**. Учитываются коллектор вида,
постоянное/временное скрытие, стадия и обрезка. Проверка габаритов относительно обрезки нужна только для
видимости, она не используется для принадлежности прибора пространству. Связанные инженерные приборы
не анализируются.

При включённых обеих галках радиаторы и решётки, видимые одновременно на одном плане, дают **ошибку
оформления всего плана**, даже если находятся в разных пространствах. До исправления видимости и разделения
планов по системам на таком виде не создаётся ни одной марки; другие выбранные планы обрабатываются.
Ошибка и ID приборов выводятся в отчёт KPLN, число ошибочных планов — в итоговый диалог.

Для связи с пространством сначала проверяются штатная `FamilyInstance.Space[phase]` и точка расчёта
пространственного элемента. Если точки расчёта нет, используется точка размещения экземпляра.
Принадлежность подтверждается `Space.IsPointInSpace` с исходным Z; при отсутствии штатной связи ищется
единственное пространство плана, содержащее эту точку. Отсутствующая/неоднозначная принадлежность выводится
в отчёт. Проекция сверху и привязка к ближайшему пространству не выполняются.

Вариант будущего алгоритма для решёток выше объёма пространства (сейчас **не реализован**):

1. Сначала штатная принадлежность и точка расчёта, с фазой вида.
2. Если принадлежности нет — вертикальная проекция вниз с неизменными XY на реальные объёмы пространств
   обслуживаемого этажа/стадии. Кандидат — первое пространство под решёткой.
3. Ограничить вертикальный зазор отдельной настройкой; не переходить через межэтажное перекрытие
   и не выбирать пространство другого этажа. При проверке архитектурных связей учитывать их трансформации.
4. Если кандидат не единственный или привязка не подтверждена — отчёт и явный выбор пользователем;
   не назначать ближайшее пространство по расстоянию в плане.

Дополнительная проверка в Revit: сохранение/чтение Shared-конфига двумя пользователями, отсутствие типов
в другой модели проекта, отдельные планы отопления/вентиляции с фильтрами, временное скрытие,
видимый смешанный план, приборы у границы пространства и решётки выше верхней границы.

API: [точка расчёта экземпляра](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/433caf59-49b1-97df-38ac-8f01a620bef5.htm),
[пространственные точки семейств](https://help.autodesk.com/cloudhelp/2024/ENU/Revit-API/files/Revit_API_Developers_Guide/Revit_Geometric_Elements/Family_Instances/Revit_API_Revit_API_Developers_Guide_Revit_Geometric_Elements_Family_Instances_FamilyInstances_html.html).
