# Проверка документации моделей KPLN
Перед проверкой читать VERSION, rules/index.md и rules/precedence.md.
Содержательные правила, допуски, методика и шаблоны принадлежат этому набору.
В установленном скилле оставлять только поиск корня и ссылки на порядок работы.
Не смешивать проверку рабочей документации с оформлением ОВ или оценкой кандидатов.
Не распространять локальные допуски на другие отделы/проекты без решения пользователя.
При изменении правил указывать источник, область действия и основание переопределения.
Данные реальных проверок хранить на диске C: пользователя согласно rules/storage.md. На X: — только правила, их источники, методика, шаблоны и служебные скрипты.
Проверка по умолчанию читает модель через существующий мост. Не управлять рабочим
столом, не переключать виды и не выделять элементы без отдельной просьбы пользователя.
Изменение правил не является заданием на изменение модели или DLL моста.
