# KPLN_ModelDocumentationCheckRules

Проверка ручных данных поверх BIM-модели и спецификаций: тексты вместо марок,
ручные количества, наложения на таблицы, размерные переопределения и расхождения.
Используется существующий KPLN_RevitMcpBridge; это слой правил, не новый сервер.

## Где что хранится

- `rules/index.md` — точка входа и порядок чтения.
- `rules/common.json` — действующие общие правила и допуски для всех моделей KPLN.
- `departments/<department>/rules.json` — правила конкретного отдела.
- `projects/<project>/departments/<department>/rules.json` — правила отдела на проекте.
- `registry.json` — явный реестр отделов/проектов и путей слоёв.
- `rules/precedence.md` — приоритеты, источники решений и работа с неизвестным контекстом.
- `rules/review-workflow.md`, `rules/bridge-contract.md`, `rules/report.md` — методика.
- `rules/decisions.md` — решения из обсуждения и границы допусков.
- `scripts/resolve_rules.py` — сбор применимых правил с цепочкой переопределений.
- `templates/layer.json` — структура нового слоя; не применяется автоматически.
- `skills/kpln-model-documentation-check/` — исходник короткого скилла.
- `rules/storage.md` — хранение результатов на C: пользователя; на X: результаты проверок не сохранять.

Приоритет: общие → отдел → проект и отдел. Более узкий слой изменяет правило
по его стабильному ID и обязан объяснить изменение. Отсутствие правила в слое
означает наследование, а не отмену. Неизвестный проект/отдел не угадывается.

Согласованные Header-спецификации, расчётные значения и предупреждения по
характеристикам систем с 26.10.2026 действуют **для всех моделей KPLN**.
В ОВ, АР и проектных слоях МТРС/ПАР1 для этих разделов пока нет дополнительных
исключений: соответствующие слои пусты явно. Они наследуют общий набор.
Общие правила работают для остальных разделов и без записи в реестре.

Пример (Python 3.10+):
`python scripts/resolve_rules.py --department OV --project MTRS_PAR1`

Для явного запроса «только общие»:
`python scripts/resolve_rules.py --department AR --project MTRS_PAR1 --common-only`

Фильтры листов и стадии относятся к запуску, а не к допускам раздела/проекта.
Порядок и примеры расширения набора: `rules/precedence.md`.

Установка скилла: `scripts/install-skill.ps1`. Установленная копия содержит
SKILL.md, UI-метаданные и rules-root.txt. Полные правила остаются на X:.
Проверка набора: `python scripts/validate_rules.py`; сценарии наследования:
`python scripts/test_resolver.py`.

Здесь нет готового универсального движка проверки RVT. Резолвер собирает
политику; агент выполняет методику через мост. Исторические скрипты конкретной
модели в локальном архиве пользователя не являются готовыми общими проверками.
