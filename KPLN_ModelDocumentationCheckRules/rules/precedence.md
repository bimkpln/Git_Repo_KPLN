# Область действия и наследование

Порядок: `common` → `department` → `project_department`:

| Слой | Путь | Область действия |
|---|---|---|
| Общий | `rules/common.json` | Все модели, разделы и проекты KPLN |
| Раздел/отдел | `departments/<department>/rules.json` | Только выбранный раздел во всех проектах |
| Проект и раздел | `projects/<project>/departments/<department>/rules.json` | Только выбранная пара проекта и раздела |

В этой архитектуре «отдел» и «раздел» — один ключ `department`, а не два слоя.
Отдельного проектного слоя для всех разделов нет: согласован третий слой именно
для пары проект + раздел. При одинаковом rule.id
последний применимый слой заменяет запись целиком. Требуются `overrides: true`,
`reason`, `source`, `condition`, `disposition`, `severity`, `active`.
Неявное слияние условий и исключений запрещено: оно расширяет допуск незаметно.
Неизвестный ID с overrides=true — ошибка. Повтор ID внутри слоя — ошибка.
Отключение выполняется записью active=false с основанием; удаление из локального
слоя возвращает наследуемое правило. Новые критерии могут иметь новые ID.

Каждая запись обязана иметь источник решения. Наблюдение по одной модели,
название семейства, координаты и количество найденных объектов — не разрешение
на новую норму. Новые общие допуски вводить по явному решению пользователя;
ведущий слой может конкретизировать условие, ответственность или критичность.
Источник — прослеживаемая запись решения, не выдуманная подпись согласующего.

Ключи OV, AR и MTRS_PAR1 — ключи этого реестра, не назначение официальных кодов компании.
OV соответствует ОВ, AR — АР. MTRS_PAR1 — подтверждённый контекст проверок ОВ и АР;
не распространять его по частичному совпадению имени файла. Связь модели с контекстом
подтверждать по заданию/данным проекта. Сходное имя не является доказательством.

Если отдел не установлен, применяются только общие правила. Если известен отдел,
но не проект — общие и отдел. Неизвестные ключи выводятся предупреждением;
локальные допуски не подбираются по похожим названиям. Реестр может указывать
явно пустой слой: это означает отсутствие дополнительных требований.
Пути слоёв ограничены корнем набора; правила не загружаются из соседних каталогов.

Если пользователь явно просит «пока только общие», вызвать резолвер с
`--common-only`. Известные `--department` и `--project` сохранять для контекста:
они не активируют локальные слои в этом режиме. В результате фиксируются
`selection_mode`, выбранный контекст и список реально прочитанных слоёв.
Без этого флага применяются все зарегистрированные подходящие слои по порядку.
Общие правила работают и для разделов, которых ещё нет в реестре; нельзя назначать
им чужой отдел ради запуска. Новый раздел регистрировать пустым, пока нет
согласованных дополнительных требований или исключений.

Выбор листов, групп, стадии и конкретной модели — охват отдельного запуска,
а не допуск. Например, прежний фильтр «уровень группировки 1 = • СТАДИЯ Р»
не превращается в ограничение всех моделей KPLN или всего проекта.
Номера листов, ID элементов и выводы конкретной проверки остаются на C:.

Новые слои: скопировать templates/layer.json, заполнить scope и правила,
зарегистрировать путь в registry.json, выполнить валидатор и сценарии наследования.
Изменять VERSION и CHANGELOG.md при выпуске изменённой политики.
