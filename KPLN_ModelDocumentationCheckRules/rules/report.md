# Понятный HTML-отчёт

Основной результат — автономный HTML с встроенными изображениями, без CDN.
Карточка: важность + уверенность, номер/имя/группа листа, ID листа/элемента,
короткое описание того, что видно, последствие и действие. Для каждой critical,
medium и warning — читаемый фрагмент, увеличение по клику, подпись источника.
Для всех карточек (critical, medium и warning) обязательно добавлять простые зелёные прямоугольные рамки
вокруг видимых проблемных мест. Без облаков и дублирования ID на изображении: ID
уже указаны в карточке. На каждом фрагменте выделить предмет замечания. Рамки не должны закрывать текст или значения; проверять положение
визуально. Выделять только реально видимые примеры, не утверждать, что показаны
все ID группы. При увеличении рамки должны сохраняться. В подписи отличать
выделение отчёта от графики исходного чертежа. Использовать существующие свежие
фрагменты; для одной разметки не требуется повторное чтение модели или печать.
Допустим векторный слой поверх неизменённого изображения.
Источник: USER-GREEN-FRAMES-ALL, 26.10.2026; заменяет ограничение USER-GREEN-FRAMES только критичными; общий формат отчётов KPLN.
Если точная ячейка не доказана, писать «подозрение», не «объём подменён».
То же правило относится к заголовку карточки: он не должен превращать suspected
в установленный факт. Для 2D-имитации назвать и подозрение, и проверенный охват.
Группируя несколько ID, сохранять связь каждого ID с его текстом и фрагментом;
если на иллюстрациях только примеры группы, явно указывать это.

Фильтры: Все / Критичные / Средние / Предупреждения, поиск по листу, ID и тексту,
счётчик показанных карточек, пустое состояние и явный сброс. Проверить все категории,
совместную работу с поиском, сброс, загрузку всех изображений и увеличение.
Для теста HTML использовать браузерные средства без перехвата рабочего стола/Revit.
Если предпросмотр запрещает JavaScript, не называть фильтры сломанными без проверки
в обычном браузере; указать пользователю рабочий способ открытия.

Подробности методики и покрытия спрятать в раскрываемый блок. Допуски показывать
отдельно от замечаний; не превращать разрешённые значения в шум предупреждений.
В отчёте сохранить версию правил, контекст/слои и source применённых исключений.
Указать режим selection_mode и реальное количество проверенных листов. Отдельно
перечислить охват аннотаций, таблиц и сверки с геометрией: прочитанная спецификация
не означает, что проверены все её количества. Известный отдел не означает, что
его слой применялся при явном режиме «только общие».
ID не является глобальным идентификатором между моделями — рядом хранить документ
и UniqueId в данных отчёта. Новое правило не делает старый отчёт автоматически верным.

Результаты сохранять только на C: пользователя по rules/storage.md; не в набор правил на X:.
