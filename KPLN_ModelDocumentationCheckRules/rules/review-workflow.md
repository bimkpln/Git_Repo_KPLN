# Проверка ручных данных поверх модели

## Полнота выборки

Зафиксировать документ, ревизию и исходный запрос (группы, листы, включая СО).
Сохранить точные ограничения запуска отдельно от правил: выбранный лист, значения
параметров группировки/стадии, режим слоёв. Повторная проверка одного листа требует
свежего чтения этого листа и всех его размещений; прежние межлистовые выводы не
выдавать за результаты нового запуска. В отчёте посчитать листы, виды и спецификации
раздельно; указать, какие количественные сверки выполнены, а какие не выполнялись.
Разрешить группы по реальным параметрам листов, не по одному видимому имени.
Перечислить все целевые листы и размещённые виды/легенды/фрагменты спецификаций.
Читать аннотации **непосредственно каждого листа**, а также размещённых видов;
лист спецификации нельзя пропускать из-за отсутствия viewport. Все страницы API
дочитывать; записывать покрытие, ошибки, лимиты и ревизии. Общий вид на нескольких
листах читать один раз, но сохранять каждое размещение.

Отдельно собрать TextNote, типовые аннотации, марки с целями, размеры с overrides,
табличные семейства, маскирующие/залитые области, изображения/импортированную графику
в области таблиц, насколько API это позволяет. Отсутствие доступа к категории —
пробел проверки, а не нулевое число элементов. Имя типа не доказывает содержание.

Для каждого кандидата: ID/UniqueId, владелец, прочитанный текст/параметры, тип,
цели марки, bounds/location и система координат, размещения на листах.
Числовой ElementId не передавать как UniqueId: найти соответствие через коллекцию.
Отсутствие ID в предыдущей выгрузке не доказывает ни корректность, ни дату создания.

## Наложения и классификация

Пересечь габариты текстов/аннотаций/масок с габаритами каждого фрагмента спецификации
в координатах листа. Для аннотаций вида сначала требуется корректное преобразование
через viewport (масштаб/поворот/центр); без преобразования пересечение не вычислять.
Учитывать пустоты bounds, видимость, обрезку, перекрытие и реальную печать.
Число, марка или единица внутри таблицы — кандидат, а не автоматически доказанная подмена.
Проверять всю таблицу, не только количества: позиция, наименование, марка, размер,
единица, количество, масса, итоги. Ноль — тоже значимое значение.

Различать: `confirmed` — смысл и нарушение подтверждены; `suspected` — есть
объективный признак, но не доказана конкретная ячейка/видимость; `allowed` —
выполнены условия конкретного допуска; `not_checked` — данных недостаточно.
Критичность и уверенность независимы. Нельзя повышать уверенность ради отчёта.
Сначала проверять условия общих/локальных допусков. Header и расчётные значения
не являются основанием исключить все тексты на листах спецификаций.

Ручные П2/В2 вместо связанных марок — пример critical в исходном разборе;
ИТП и В21 — medium по контексту того разбора. Не переносить классификацию по
самой строке текста: на другом листе та же строка может иметь другую функцию.

Подписи лифтов, оборудования и других элементов проверять тем же способом:
марка и грузоподъёмность/характеристика, набранные TextNote, могут имитировать
данные модели. Подтверждённый ручной способ не доказывает неверность самого числа.
Образцы марок в легенде, текстовая ссылка на узел или пояснение не являются
автоматически имитацией параметра реального элемента.

## 2D-графика вместо модельного элемента

Собирать элементы детализации и залитые/маскирующие области отдельно от обычных
аннотаций, в том числе вне таблиц. Для кандидата прочитать категорию, OwnerView,
параметры типа/экземпляра, маскирование и материал/штриховку; сопоставить положение
с актуальной печатью и с ожидаемыми модельными категориями.
Не выводить назначение только из имени семейства или типа.

Если на рабочем виде 2D-графика изображает элемент, но соответствующий модельный
объект в проверенном охвате не найден, применить DOC-2D-MODEL-IMITATION как
critical + suspected. В карточке назвать фактический охват поиска: текущий документ,
категории, видимость, связи и доступные геометрические данные. Проверка габаритов
потенциально видимых стен не доказывает отсутствие стены в связях, скрытых элементах
или иных категориях. Само пересечение bounds не доказывает точную геометрию.
К confirmed переходить только после установления назначения и достаточной сверки.
Схемы, легенды, узлы и обычные области оформления требуют проверки контекста,
а не автоматического замечания. 2D-элемент сам по себе не создаёт модельный объём.

## Спецификации — две независимые проверки

1. Содержимое: Header и Body, колонки/единицы/фильтры/сортировка, формулы и округление
   при доступности. Сопоставить строки с элементами, экземплярными и типовыми
   параметрами; ключ включает как минимум позицию и единицу, при необходимости
   систему/наименование/тип. Не суммировать разные изделия с одинаковой позицией.
   Дублирующаяся позиция у разных изделий — отдельное замечание.
2. Представление: отдельные тексты/семейства/маски поверх размещённой таблицы.
   Совпадение всех Body-значений с параметрами не закрывает эту проверку.
   Также проверить взаимное наложение фрагментов разных таблиц. Если на печати
   строки перекрывают друг друга и теряется читаемость — DOC-TABLE-OVERLAP,
   medium. Это не доказательство ручной подмены количества. Отдельная ручная
   цифра, выдающая объём/количество за значение модели, оценивается независимо
   по DOC-QUANTITY-SUBSTITUTION и при доказательстве остаётся critical.

Сверка суммы параметров не доказывает геометрические объёмы и полноту включения
всех объектов проекта. Отдельно учитывать исключённые фильтрами элементы и запас.
Округление короткого участка до 0 и запас допустимы при доказанном источнике;
не выдавать их за критичную ошибку автоматически. Если формулы API не читает,
указывать ограничение, даже при совпадении арифметического результата.

## Иллюстрации без управления рабочим столом

Использовать доступные PDF/экспорт изображений через API моста; проверить наличие,
сигнатуру, количество страниц и пригодность изображения. Печатать только в файл.
Не переключать виды, не выделять элементы show=true, не нажимать кнопки и не
снимать рабочий стол автоматически. Сбой экспорта не разрешает обход через UI.
Read-only запросы и экспорт занимают Revit: дробить работу и не запускать массовые
повторы при таймауте. Не утверждать, что фоновые запросы не нагружают Revit.

Если картинки получить нельзя, сохранить доказательства и честно отметить отсутствие
иллюстрации; не объявлять требование выполненным и не рисовать вымышленный скрин.
При необходимости уточнить у пользователя доступный путь экспорта, продолжая
независимый анализ. Отдельная просьба об управлении UI меняет только этот способ,
не даёт разрешения редактировать модель.
